## 三、逐条

### 1. 数值系统没进包

**现象**：`creator_notes` 告诉玩家「成人内容以好感度 ≥ 55 为前提（慢热）」，14 张卡的 `nsfw` 块也按「堕落度五段」写了行为，但模型手里没有这些数。

**证据**（对 `最终产物/st/爱情公寓.json` 的 `data.description` 与 14 条世界书做计数）：

```
「好感度」0 次　「堕落度」0 次　「corruption」0 次　「affection」0 次　「阈值」0 次
system_prompt：59 字，仅 H07 一条
世界书：14 条，无一条定义轴
```

**根因**：`stage-7-delivery.md:96` 规定 `description` = 世界观 YAML 全文 + 分隔 + 角色卡 YAML 全文，**没有轴**。同一文件 `:178` 的肉眼自检却要求「轴名逐个能在 `description` 里找到」——规则互相矛盾，产物按前者生成、后者自然不成立；而 `scripts/validate-st-package.py` 的 X01 只输出字数。

**建议改法**：
1. `:96` 补第三段：「+ 数值系统 YAML 全文（只留 `axes` / `thresholds` / `calc_mod` / `calculation` / `anti_exploit`，删 `meta.purpose` 这类给人看的说明）」。
2. 新增校验 `X02`：`description` 必须包含每个 `contract.naming.axes[].name`，否则 FAIL；`nsfw: true` 时应至少命中 1 条轴名。
3. `:178` 那条肉眼自检改成「轴名若出现在 description，必须与契约一致；不出现则 FAIL」——把含糊的"能找到"变成判定。

### 2. 一条轴套 14 个人

**现象**：`好感度.yaml` 只有一条 `affection`，`purpose` 写「**她**愿不愿意让你靠近」；`堕落度.yaml` 同理。14 张卡的 `nsfw` 块用同一套堕落度阈值写行为。

**后果**：全局数值到 60，胡一菲与咖喱酱一起变；玩家对某个人的经营没有独立反馈。群像剧的数值等于装饰。

**根因**：`stage-4-axis-system.md:19` 的充分性评估只问「对象：可确定系统作用于谁」，没有「对象是否多于一人」这一支；`templates/axis-system.yaml` 也没有多目标维度。

**建议改法**：
1. 在阶段 4 判断标准加一节「多目标」：若 `contract.naming` 的角色数 ≥3 且轴语义是「某人对玩家的态度」，必须选一种实现——(a) `targets: [char_x, char_y, …]` 每条角色一行数值（推荐，写进 `axes[].targets`）；(b) 明确降级为「整栋楼的气氛值」并写进 `decisions`，同时在产物里改名避免误导（`affection` → `building_mood`）。
2. 模板加 `targets` 字段与示例。
3. 契约 `naming.axes[]` 加 `multi_target: true|false`，阶段 7 拼接 description 时按 `targets` 生成「每人一行当前值」。

### 3. 场景卡在包里命中 0 条

**现象**：9 张场景卡、53 条「现场可见」原句，拿去和 `description` + 世界书比对，**命中 0/53**。

**根因**：`stage-7-delivery.md:78` 明确「场景卡不进世界书」，切法表里也只切 `world-bible`。于是阶段 3 的产出对酒馆包零贡献——而它在原作校准那轮还被专门重写过（户型、电梯、电台档期）。

**建议改法**（选一，写进 `:78`）：
- **A（推荐）**：场景卡的 `空间结构` + `关键区域.现场可见` + `出入口与安防` 各出一族关键词条目（`key` = 场景名 + 区域名），与世界观条目共用预算；这样"客厅只有一张长沙发、卫生间只有一个"这类硬事实才进得了上下文。
- **B**：不做条目，但在阶段 3 的退出条件与 README 里写清「酒馆路线下场景卡只给人看，AI 不会读到」；并在阶段 7 的交付说明里向用户交代，避免用户以为做了白做。
- 无论选哪个，`stage-7-delivery.md` 都要加一句「场景硬事实若已进世界书，`description` 不再重复」。

### 4. `description` 70,134 字

**证据**：汉字 32,706、其余 37,428，粗估 **43k token**；加世界书常驻 4,441 字，最低每轮注入约 **74k 字**。32k 模型直接不可用，64k 模型只剩 5–10k 给对话。

**根因**：`:96` 是线性叠加规则（1 个角色时合理）。阶段 2 的档位表允许「全员标准档」（这次就是），但没有任何总量上限。

**建议改法**：
1. `:96` 加预算：`description` 目标 ≤ 20,000 字，硬上限 30,000 字；超了就按优先级裁——先删每位角色的 `background` / `attitudes`（交给世界书关键词条目），再删重复段。
2. 阶段 2 档位表加一列「角色数 ≥6 时」：默认「主角标准档 + 其余精简档」，全员标准档需用户明确要求并提示 token 成本。
3. 校验器新增 `X03`：`description` > 30,000 字 FAIL，> 20,000 字 WARN（并打印粗估 token）。
4. `creator_notes` 现有的「建议 64k 以上上下文」不算解决方案——它把成本转给了用户，且这次连数值都没进去，用户无从判断。

### 5. 世界书常驻与 `description` 重复

**证据**：6 条常驻（4,441 字）分别由 `world-bible.yaml` 的 `世界怎么运转`、`这栋楼的默契`、`变更边界`、`这个世界在说什么` 等段生成；同一批段落已在 `description` 里。

**根因**：`:29` 写着「一条设定只写一处」，但 `:96`（description 装世界观全文）与切法表（世界观再切一份进世界书）使这句话必然被违反。

**建议改法**：明确二者的分工并写进 `:96` 的注释——`description` 只放**每轮都必须在场**的东西（人物人设 + 世界骨架一句话），世界书放**按需出场**的东西；常驻条目只允许「不可以按需」的 3–5 条，且每条 ≤600 字。

### 6. 构建期占位符漏进运行时

**证据**：

```
description：【AI补全·可替换】15 次、[待定 5 次
世界书：      [待定 6 次、【AI补全·可替换】1 次
```

典型位置：`新住户接入规则.<user>_模板.默认设定` 直接以 `【AI补全·可替换】刚毕业两年的自由职业者……` 开头；14 张卡的 `unknown_handling` 都写着「新增内容一律标【AI补全·可替换】」。

**根因**：`templates/rolecard.yaml:157` 的 `unknown_handling` 是**构建期话术**（"推理时请标占位符"），落到卡里就变成**运行时指令**（"扮演时请输出占位符"）。skill 只有「终稿不含台账块」一条，管不到这种字段级泄漏。

**建议改法**：
1. 模板 `:157` 改成运行时口径，例如「遇到设定未覆盖的情况，从 `psychology.motivations` 与 `values.ranking` 推断，推理依据不写进正文」——把"打标记"留给构建者，产物里不出现标记。
2. 阶段 2 / 阶段 7 各加一条自检：`grep -c '【AI补全\|\[待定\|【未知】' 产物` 必须为 0（写进阶段 7 的校验器作为 `X04`）。
3. `[待定]` 只允许留在 `创作痕迹/contract.yaml` 的 `pending`，产物值域里不允许出现。

### 7. NSFW 开关没贯穿阶段 2

**证据**：`stage-2-rolecard.md:123`——「内容边界层那一类**仅当** `content_boundaries.nsfw: true` **且卡里有 `nsfw` 块**时执行」。这次 14 张卡都没写块，于是整类检查静默跳过；用户在第 3 轮才发现。

**根因**：把「产物自己有没有这个字段」当成检查前提。缺块本应是 FAIL，条件写法却让它变成 SKIP。`:119` 只规定了 `nsfw: false` 的分支。

**建议改法**：`:123` 改成两条独立判断——
- `nsfw: true` → 「卡里必须有 `nsfw` 块且七键齐全；缺块 = 自检失败，回阶段 2 补」，不再由"有没有块"决定要不要查；
- `nsfw: false` → 「卡里不得出现 `nsfw` 块；`taboos` / `anti_ooc.never` 必须包含『不做任何性行为』」。
另外在阶段 2 的"生成"节，把 `nsfw` 显式写进档位表的「标准档 = 模板全部基础字段**，`content_boundaries.nsfw: true` 时附加 `nsfw` 块**」。

### 8. 模板遵守靠自觉

**现象**：阶段 2 前两轮自造 schema（`档位 / 归属势力 / 登场期 / 一句话 / intimacy`），用户原话「错误的，你并没有按照原始 yaml 模板进行写」，第三轮才按模板重写 14 张。

**根因**：`stage-2-rolecard.md` 只说「骨架：`templates/rolecard.yaml`」，没有「逐键抄骨架、再填」的动作要求，也没有校验器——阶段 7 有 `scripts/validate-st-package.py`，阶段 2 没有对应物。

**建议改法**：
1. 阶段 2 生成节第一步写死：「先把 `templates/rolecard.yaml` 的键树整份复制过来，再填值；不许新增顶层键，扩展块只用 `lore` / `relationships` / `growth_arc` 三个」。
2. 新增 `scripts/validate-rolecard.py`：查九大块齐全、`taboos ⊆ anti_ooc.never`、`behavior.rules` ≥4 且每条含 `trigger` + `action` + 二选一（`condition` / `reason` / `cost`）、`speech.rules` 四类齐、`nsfw` 七键齐，退出码 0/1。阶段 2 的退出条件改成「跑脚本」。

### 9. 世界观模板强制「核心矛盾」

**现象**：第一版被否「整个世界观写成了一个严肃的审判世界，任何事件的因果都是围绕在某个东西」，第二版被否「你再去联网看，《爱情公寓》它到底在说些什么」。最终稿把 `核心矛盾` 整块删掉，新增 `世界怎么运转`、`日常生活的质地`、`谁跟谁放一起会出事`——模板里这三块都没有。

**根因**：`templates/world-bible.yaml:52` 的 `核心矛盾` 是第二块，且 stage-1 把「核心矛盾方向」列为四大框架要素（`:15`）、原则 5 要求让用户拍板（`:45`）。对一个情景喜剧沙盒，"核心矛盾"这个字段名会逼模型造出单一因果引擎——字段名的语义引导比任何风格说明都强。

**建议改法**：
1. 模板把 `核心矛盾` 改名为 `张力从哪来`，并允许多源（不是单一引擎）：给三个子键 `日常张力` / `关系张力` / `外部张力`，各写"它长什么样 / 它怎么闹大 / 它怎么收场"。
2. 新增可选块 `日常质地`（一天的节奏 / 吃什么 / 钱怎么周转 / 怎么玩 / 传闻怎么流）与 `怎么运转`（沙盒还是任务制、AI 的职责清单、世界自发动静、卡住时的兜底）。
3. stage-1 的四大要素把「核心矛盾方向」改成「张力形态（单一引擎 / 多源日常 / 任务线）」，并把"沙盒"作为一等选项。
4. 若用户选沙盒，阶段 1 的收敛门额外要求 `世界怎么运转` 与 `日常质地` 非空。

## 四、建议的修改顺序与验收

不做「全部一起改」，按这个顺序，每步都能独立验收：

1. **数值进包 + 多目标轴**（1、2）→ 验收：`X02` 通过；`好感度.yaml` 里每人一行；`description` 里能 grep 到 `affection` 与每人当前值。
2. **description 预算**（4、5）→ 验收：`X03` ≤30,000 字；常驻世界书 ≤3,000 字；`description` 与世界书无整段重复。
3. **场景卡去向**（3）→ 验收：场景硬事实能在世界书里 grep 到，或交付说明里明写"只给人看"。
4. **占位符与 NSFW 条件**（6、7）→ 验收：`X04` 占位符 0 命中；`nsfw: true` 的卡必定有 `nsfw` 块。
5. **角色卡校验器 + 世界观改名**（8、9）→ 验收：`validate-rolecard.py` 退出码 0；沙盒题材能生成 `世界怎么运转`。
6. **契约白名单**（10）→ 验收：`artifacts[].type` 全部在枚举内。

## 五、不能误伤的部分

这次产物里有几处是**做对了**的，改 skill 时别把它们改掉：

- 世界观 `世界怎么运转` 那一段（AI 职责 / 自发动静 / 五步兜底）是本包最有价值的部分，建议提为模板一等公民，别只当补充。
- 角色卡的 `behavior.rules`（`trigger` + `action` + `cost`）是可执行的好格式，比"性格描述"有用得多。
- `stage-7` 的「世界书名 = 世界书文件名 = `extensions.world`」这条硬事实救了这次导入。
- NSFW 层「写得到 ≠ 写得出，慢热由数值闸门保证」这个拆分思路是对的——问题只是闸门没进包。

### 6.1 联网只在被点名时发生

**现象**：`project.web_research: true`，但阶段 2 第 2 轮补检索（S18–S28）、阶段 3 补检索（S29–S31）、"校对轮"整轮（S32–S39）都是用户说「再去联网看」之后才发生的。

**根因**：规则在 `SKILL.md` 的开局四问里写得挺硬（"此后不管创作什么……落笔前都先检索再用"），但**阶段文件里没有对应的动作**。模型进阶段时读一次 `stage-N-*.md`，此后连续 6 轮写作都不再回头看 `SKILL.md`，于是"落笔前检索"这条只存在于它进门那一刻的记忆里。`references/web-research.md` 第一节虽然列了"何时检索"的表，但它是独立文件，阶段文件没有在 `## 生成` 的开头引用它。

**建议改法**：
1. 每个 `stage-N-*.md` 的 `## 生成` **第一句**固定为：「`project.web_research: true` → 本步动笔前先按 `references/web-research.md` 检索，新增条目写进 `检索来源.md`；查完再写。」
2. `stage-N-*.md` 的 `## 进入条件` 里把它从"条件"改成"每轮动作"：进入条件只判一次，检索是每轮都要做的。
3. 在 `pipeline.md` 的八道门里加一道 `检索门（仅 web_research: true）`：本阶段新增/修改的设定，每条要能指到一条 `S##`；指不到就是凭空写的，停下补检索。
4. 每阶段收尾汇总时，必须报「本阶段新增检索 N 条 / 补检索 M 次」，让用户看得见它有没有查。

### 6.2 不问就写完（"自我高潮"）

**现象**：阶段 1 从第 2 轮起连续 6 轮自写自改，其中两次是用户看到成品才否掉的（审判世界、引擎用错）；阶段 3 用户放弃作答后，模型直接按自己的推荐项做完了 9 张场景卡。

**根因**（三条，都在 `references/interview-protocol.md` 与各阶段文件里）：
- 「用户委托决策 → 自主补全」被写成了默认路径，而**"用户放弃作答"被当成了"委托"**。放弃是"我现在不想选"，不是"你替我定"。
- 各阶段写的是「充分性评估三项全满足则直接生成」——只要模型自认为满足，就可以一路写完，没有"先给一版骨架让用户点头"的中间态。
- 追问预算按"轮"计（如阶段 1 后续每轮 ≤8 问），模型为了不浪费轮次，倾向于一次问完再一次性写完，中间没有检查点。

**建议改法**：
1. 「用户放弃作答 / 未选」→ 明确不视为委托：停下来给一句话确认（"这几项你不选，我先按推荐做，做完你直接改"），用户点头再动；不点头就停在该轮。
2. 每个阶段加**两个检查点**：① 骨架点（首轮问完，先给"我准备这样写"的 5–8 行结构，用户点头才写全文）；② 定稿点（全文写完，停下来等确认，不自动进下一阶段）。
3. 追问预算的单位从"轮"改成"产物"：**一轮对话只允许推进一件事**（问完 / 或写完一份产物）。写完就停，不许连着写第二份。

### 6.3 阶段连跑，不停

**现象**：阶段 1 定稿 → 直接进阶段 2；阶段 2 完成 → 直接进阶段 3；阶段 7 选完路线 → 直接生成包。用户的描述是"一个阶段完成了直接发起工具选项弹窗"。

**根因**：`SKILL.md` 只写了「执行顺序永远 1→2→3→4→5→6，不跳序」，`references/pipeline.md` 只有阶段表与门，**全书没有一处写"阶段做完要停"**。顺序规则在没有停点的情况下，自然被读成"连续执行"。

**建议改法**：
1. `pipeline.md` 阶段表下面加一节「阶段收尾必停」，写成硬规则：每个阶段 `done` 之后，只允许输出**收尾汇报**，不许在同一轮里开始下一阶段。收尾汇报固定四行：交付了什么 / 没做什么（含 `skipped`）/ 待你确认的 3 条以内 / 下一阶段会问什么。
2. 阶段切换只能由用户发起：用户说"继续 / 进下一阶段 / 做角色卡"才动；模型自己不许用选项弹窗替用户发起。
3. `SKILL.md` 的「执行顺序永远 1→2→3→4→5→6」后面补一句「但这不表示连续执行：每阶段收尾必停，等用户发起」。

### 6.4 NSFW 开关形同虚设（范围比第二节 #7 更大）

**现象**：不只是"卡里没写 `nsfw` 块"。整个阶段 1 与阶段 3 对 R18 没有反应：世界观的 `信息分层`、`AI即兴角色约束` 里没有任何成人向约束；9 张场景卡也没有一张写到亲密空间的可判定性（门锁、隔音、床、时长）。

**根因**：
- `references/stage-1-world-bible.md:122` 只规定了 `nsfw: false` 的分支（"不得出现任何性描写"）；`true` 时该写什么，一句没有。
- `references/stage-3-scene-sheet.md:67` 把内容边界层写成"仅当本场景确实涉及性内容时执行"——又是一个"没做就不查"的条件。
- `stage-2` 的 `nsfw` 块被当作可选装饰（见第二节 #7），而它是 `nsfw: true` 时唯一真正影响演出的字段。

**建议改法**（三处，缺一不可）：
1. 阶段 1：`nsfw: true` 时 `AI即兴角色约束` 必须含"亲密场景的准入与收场"两条；`信息分层` 必须含"哪些身体/关系信息是公开、半公开、只有本人知道"。
2. 阶段 3：`nsfw: true` 时每张场景卡的 `边界` 必须写「可发生 / 不可发生 / 被打断的方式」三行；`出入口与安防` 必须写门锁与隔音（这是亲密戏的可判定性来源）。
3. 阶段 2：把 `nsfw` 块从"可选"改成"`nsfw: true` 时必填"，并让自检从 SKIP 变 FAIL（第二节 #7 已列）。
4. 阶段 7：`description` 必须带一个「亲密场景协议」段（准入轴 / 尺度上限 / 收场方式），否则 `nsfw: true` 的包等于没有边界。

### 6.5 自创字段：这次弊大于利

**现象**：这次自创的东西有一半是好的（`世界怎么运转`、`日常生活的质地`、`秘密层`），另一半是坏的（`intimacy` 块、`role-cards` / `secret-layer` 两个越界的 `artifacts.type`、`stages.1` 停在 `partial`）。用户对 `intimacy` 的判决是"错误的，你并没有按照原始 yaml 模板进行写"。

**根因**：skill 对"扩展"只有一处软描述（`stage-2` 档位表里的 `lore` / `relationships` / `growth_arc` 三个扩展块），既没说"不许自创顶层键"，也没说"自创要满足什么条件、记在哪"。

**建议改法**（把"允许"变成"有条件的允许"）：
1. 三条准入：① 模板没有、且**不加就演错**；② 只能挂在扩展块下（`lore` / `relationships` / `growth_arc` / `extensions`），不许新造顶层键；③ 必须同时写进 `contract.decisions`（写清为什么不加会演错）与交付说明。
2. 阶段 2 生成第一步改成"整份复制 `templates/rolecard.yaml` 的键树再填值"，让"自创"必须先跨过"照抄"这一步。
3. `contract-schema.md` 的 `artifacts[].type` 给出**封闭枚举**，越界直接判错；`secret-layer` 若确实需要，就正式加进枚举并规定它只能落在 `创作痕迹/`。

## 七、酒馆包为什么算"错的"（对照 `我，非我`）

不是"少了一段"，是**整体拼法不一样**。把两个包逐项量一遍：

| 维度 | `我，非我`（参考） | 这次（爱情公寓） | 差 |
|---|---|---|---|

| 人物在哪 | **不进 description**。世界书里只有一条「NPC行为逻辑框架」（3,257 字），人物由框架驱动、按需生成 | 14 张卡全量塞进 description，每人约 4,500 字 | 方向相反 |
| 世界书条数 | 22 条 | 14 条 | — |
| 常驻（蓝）合计 | 11 条 ≈ **19,690 字**（含两条状态栏 4,665） | 6 条 **4,441 字** | — |
| 切法 | 按**知识块**切：名词词典 28 关键词 / 4,523 字，启示觉醒 2 关键词 / 6,184 字，武器 4 关键词 / 3,515 字 | 按**世界观的章节**切：住处 / 门外的人 / 楼外四个地方……每条 78–88 order，339–930 字 | 粒度错 |
| 分组 | 用 20 字的蓝条目当分隔标题：`——势力与社会结构——` | 无 | 少一层结构 |

| 场景 | 蓝条目「地点环境模板」2,730 字，给模板而非逐张卡 | 9 张场景卡，**包内命中 0** | 白做 |

| `findRegex` | 纯字符串 `Create_character` | `/＜建卡向导＞.../g` 带分隔符与标志 | 能用，但没必要走正则解析 |

### 7.1 这次包的具体错误（按"错在哪"排）

1. **把角色卡当设定文档塞 `description`**。参考里人物从来不是 `description` 的活；它们是"演的时候才需要"的知识，属于世界书的关键词条目。我们把 14 张 4,500 字的卡全量常驻，等于每轮都把 14 个人从头念一遍。
2. **6 条蓝条目是 `description` 的复制品**。世界规则 / 这栋楼的默契 / 变更边界 / 这个世界在说什么 在两边各一份，付双份钱。
3. **切法跟着世界观的目录走，而不是跟着"什么时候需要"走**。参考的「名词词典」28 个关键词、4,523 字，是"提到才查"的正确粒度；我们的「住处 / 门外的人 / 楼外四个地方」是章节名，触发后一次塞 300–900 字，且和 `description` 里的同一段重复。
4. **`first_mes` 用尖括号**。参考用 `Create_character` 这种不会与 HTML 标签冲突的字面串，正是为了绕开 ST 的标签处理。
5. **台账泄漏**：`description` 里 15 处 `【AI补全·可替换】`、5 处 `[待定`。
6. **场景卡与数值双双缺席**（见第二、三节）。
7. **没给 `character_book` 内嵌版**，只有独立世界书文件；用户若走"卡内世界书"那条路就没有。

### 7.2 按参考的形状重做，这包应该长这样

| 层 | 内容 | 估算 |
|---|---|---|
| `description` | 世界观一页：元信息 / 类型与基调 / 世界怎么运转 / 这栋楼的默契 / 信息分层与防剧透 / 张力形态 / 变更边界 / 数值协议摘要 / 十四人一行索引（名字 · 期数 · 住哪） | **≤8,000 字** |
| 蓝条目 | 世界规则 · 世界怎么运转 · 这栋楼的默契 · 信息分层与防剧透 · **数值协议**（含量表、档位、涨法、回落、每人当前值占位）· **亲密场景协议**（准入轴 / 尺度 / 收场） · 常识清单 · 名词词典（28–36 关键词，人名 + 地名 + 口癖 + 梗） | 8 条 ≈ 8,000–10,000 字 |
| 绿条目 · 人物 | 每人一条，关键词 = 名字 + 别名 + 昵称；正文 400–700 字：身份 / 口癖 / 命门 / 禁忌 / 与用户默认关系 / 当前期数 | 14 条 ≈ 8,000 字 |
| 绿条目 · 场景 | 每处一处：空间硬事实 + 可判定物 + 谁能进来 + 门锁与隔音 | 9 条 ≈ 3,000 字 |
| 蓝分隔符 | `——人物——` / `——场景——` / `——协议——` 这类 20 字条目 | 3 条 |
| 绿条目 · 未决 | 未决事项（763 字级） | 1 条 |
| 正则 | 两条：开局（字面串 `Create_character` 式）+ 状态栏（若做阶段 6） | — |
| 双份 | 卡内 `character_book` + 独立世界书文件 | — |

每轮最低注入：`description` 8k + 蓝 9k + 触发 1–2 条绿 ≈ **17k–19k 字（≈11k token）**，32k 模型可用；现在是 74k 字（≈45k token）。

对应 skill 的改法（不动产物格式，只动阶段 7 的拼装规则）：

1. `description` 的组成从「世界观全文 + 全部角色卡全文」改成「世界观摘要 + 人物一行索引」；全文的权威副本仍留在 `最终产物/角色卡/`，给人和给别的 AI 用。
2. 阶段 7 新增「人物条目」切法：每张角色卡 → 一条绿条目，正文从卡里**抽取**五段（身份 / 口癖 / 命门 / 禁忌 / 关系），不整卡搬运；`description` 只留索引。
3. 世界书切法表加一列「粒度」：一条目 ≤800 字、关键词 ≥8；超过 800 字的设定改写成"名词词典式"的多关键词条目，或回到阶段 1 拆 section。
4. 加分隔条目与「未决事项」条目（对照参考，前者给人读，后者给 AI 用）。
5. `first_mes` 约定改成无尖括号的字面串（如 `Create_character` / `Create_resident`），正则也用同一个字面串，不写 `/.../g`。
6. 打包时同时产出卡内 `character_book` 与独立世界书文件。
