# 试演：跑五轮，改一处

脚本验得了「文件对不对」，验不了「跑起来像不像」。这一页管后者：**在真酒馆里跑几轮，把症状记下来，映射到最小的那个字段。**

两条纪律先说：

1. **≤5 轮**。每轮只判一个症状、只改一处。五轮还不对，说明设定本身没想清，回阶段一，而不是继续调 prompt。
2. **禁止整卡重写**。整卡重写会把已经过校验的结构（卡字段、正则、世界书条目）一起冲掉，等于把交付门白跑一遍。改哪一处写在日志里，改完只重跑那一条检查。

试演结论按 `references/acceptance.md` 记 L5/L6（`by: human`），**脚本不许代签**。

---

## 先分清四类证据

症状落账前先问一句：这条结论是哪来的。四类不许混写：

| 证据 | 是什么 | 能得出什么 |
|---|---|---|
| **既有设定** | 卡里/书里已经写定的内容 | 「设定这么说」——不能证明「跑出来是这样」 |
| **实际输出** | 酒馆里真实生成的那几段 | 唯一能支持「演出手感」的证据 |
| **作者观察** | 用户或作者自己的喜好与判断 | 「不好看」成立，但病因要再查 |
| **诊断假设** | 我推的原因 | 只能当线索，除非能被上面三条之一验证 |

两条推论：

- **静态审阅证明不了演出手感**。卡写得合规、条条有据，不等于跑起来像那个人。所以 R1–R4 必须基于实际输出，不能靠「我读了卡觉得没问题」。
- **提示词没生效 ≠ 性格不够**。角色平淡先查激活与注入（R2 第一步），别先改性格。把「性格再强一点」当默认修法，是四类证据混淆的最常见后果。

---

## 最小响应集合

判定之后能做的事只有八种，按代价从低到高：

| 响应 | 什么时候用 |
|---|---|
| **不改** | 只出现过一次，可能是用户输入造成的，先攒样本 |
| **再观察** | 症状轻、但方向可疑；下一轮重点盯这一处 |
| **删** | 某条提示词/规则在拖后腿（改了反而好） |
| **缩** | 条目太长、重点被稀释——把「能/不能/代价/上限」压成一句 |
| **并** | 两条规则重复或互相抵消 |
| **挪** | 内容对但位置错（该进 @D 的写进了常驻，该进开场的写进了卡） |
| **澄清** | 词义模糊：「温柔」到底指语气还是让步 |
| **补** | 真正缺一块（缺一条反面例子、缺一个上限） |

「整卡重写」不在这张表里。它不属于最小响应，要重写就单独提、单独批准、单独跑交付门。

## 四类判据

### R1 代演玩家（最影响体验）

**判据不靠猜，靠契约里的 `player_agency.mode`**（见 `references/decisions.md` 第六节）：

- `player-controlled`（缺省）：写了玩家的动作 / 台词 / 内心 / 感受 / 决定 / 生理反应 = 代演。
- `limited`：超出 `allowed` 列的那几处 = 代演；那几处内不算。
- `delegated`：不写玩家的动作反而不对——那就成了另一种偏离。

**症状**：「你点了点头」「你决定跟他走」「你说：……」；或一轮里把用户的台词也写了。

**观测点**：连续 3 轮，数每轮里属于玩家的动作/台词有几处，并按上面三档判定这算不算越界。

**最小修法**（按代价从低到高）：

1. `post_history_instructions` 里加一句硬约束（"只写 {{char}} 的动作与台词；不替 {{user}} 决定"）——改一处、立刻见效。
2. **世界书加一条 `position: 4`（@D）+ `role: 0` 的短条目**，只在近几轮生效。
3. **用例对话（`mes_example`）补两轮「玩家只说半句、角色只回自己的」**——这是最有效的，但改动最大。

**不要**改 `description`：代演是行为习惯问题，塞进人物设定只会让角色变啰嗦。

分不清「作者让我写」与「角色自己会这样」时，回 `references/decisions.md` 第六节对一遍——客观后果可以写，主观感受不行。

### R2 OOC / 设定对不上

**症状**：叫错名字、地点错、把已否定的设定捡回来、忘了能力上限。

**观测点**：每轮回复里出现的专名，逐个对照 `naming`；出现的规则，对照 `axes` / 硬设定。

**最小修法**：

1. 关键条目没触发 → 先查**激活**而不是改文案：关键词是否出现在最近 `scanDepth` 条消息里、`order` 是否被预算挤掉（见 `references/st-correctness.md` S-11/S-12）、`position` 是否落在看不到的位置（S-10）。
2. 触发了但没遵守 → 条目太长：把"能/不能/代价/上限"压成一条短句，或拆成两条更窄的条目。
3. 名字漂移 → 回 `naming` 改一处并回写所有引用（`references/contract-schema.md` 的改名流程）。

### R3 口癖与语气漂移

**症状**：角色说话越来越像通用助手——每条都完整句、都带解释、都礼貌。

**观测点**：抽 5 句角色台词，对照语言规则条目（口头禅、句长、标点习惯）。也可跑 `python scripts/check_prose.py`——它抓的是八股形态（P03 情绪直说、P07 标签单调），提示哪句像模板。

**最小修法**：

1. `mes_example` 里换掉最像 AI 的那两轮（示例的模仿效力远高于规则描述）。
2. 语言规则条目加 1 条「禁止」而非再加 5 条「应该」。
3. 不要把口癖写进 `personality` 一句话了事——模型会把形容词当风格标签，反而更平。

### R4 数值闸门失效

**症状**：数值不更新 / 一直涨不回落 / 出现越界值（100 以上）/ 状态栏显示 `undefined`。

**观测点**：连跑 3 轮，看 `stat_data` 是否有变化、是否夹在 `range` 内。

**最小修法**：

1. 完全不动 → 先确认酒馆助手装没装（`references/st-correctness.md` S-20），再看正则里隐藏 `<UpdateVariable>` 的两条是否 `disable: false`、被控条目是否 `disable: true`。
2. 越界 → `mvu-schema` 的 `.catch(初值)` 与 clamp 上界是否等于轴的 `range`（`validate-mvu.py` 的 M 系列查过结构，这里查的是"跑了之后还越界"）。
3. 乱涨 → 更新条目里缺少"只有本轮变化才写"的约束，或概率/深度门槛没设。

## 日志

每轮一条，落在 `制作文件/试演日志.yaml`（模板：`templates/rehearsal-log.yaml`）：

```yaml
rounds:
  - round: 1
    judged: R1
    evidence: 实际输出        # 既有设定 / 实际输出 / 作者观察 / 诊断假设 四选一
    symptom: 第 2 轮替玩家点头
    root_cause: post_history_instructions 里没有禁止代演的约束
    change: {file: 导入包/测试世界（纯净）.json, field: data.post_history_instructions}
    re_observed: 第 3 轮仍是 1 处，但只发生在收尾句
  - round: 2
    judged: R1
    symptom: 收尾句仍然代演
    root_cause: 例对话里有两轮是「玩家不说话」的格式
    change: {file: 导入包/测试世界（纯净）.json, field: data.mes_example}
    re_observed: 通过
```

字段含义：`judged` 四类之一；`evidence` 四类证据之一（写「诊断假设」的条目不能当结论用）；`change` 必须落到**文件 + 字段**（写"调整了 prompt"等于没记）；`re_observed` 写下一轮实际看到什么，不写"已修复"。

五轮结束仍不过的，写清零结：

```yaml
conclusion:
  verdict: 未收敛
  reason: R4 数值仍越界，怀疑轴的上界与 schema 不一致
  next: 回阶段 axes 复核 range，不继续调 prompt
```
