# 世界书写什么：条目的文本契约

`worldbook-tuning.md` 管**怎么配**（三灯、关键词、位置、顺序、预算）。这一份管**写什么**：一条条目里哪些句子承载世界事实、哪些只能算倾向、哪些信息属于「谁知道」而不是「世界怎样」。

分工记一句：**配置能让条目被读到，文本决定读到之后模型做得对不对。** 配置全对而条目写歪，是这一包最难复盘的一类失败——界面正常、条目也激活了，只是模型理解成了另一回事。

---

## 零、条目是原稿的一节，不是它的摘要

切分动作由 `scripts/cut-worldbook.py` 完成：plan 里写「哪一节、叫什么、什么关键词」，脚本把那一节**逐行搬**进 `content`。这一份剩下的内容，管的是*万一必须动字*时怎么动（`[秘密]` 标记、分档挪位），以及原稿本身该怎么写才切得动。

三条硬边界：

- **不摘要**。《常见误解或谣言》《干预可能》《弱点》这类小节整节留着：它们正是模型判断「这个说法对不对」「这一刀够不够」时的唯一依据，压成一句就只剩空标签。
- **不合并**。两个相邻小节合成一条，模型就分不清哪句话属于哪个范围，条件规则的例外最容易在这种合并里丢。
- **不润色**。切完的措辞就是原稿的措辞；觉得原稿写歪了，回阶段 1 改原稿，再重切一次——不要在世界书里改第二遍，那会让两份文档分叉。

`validate-st-package.py` 的 `W17` / `W18` 会核这两件事：条目里有多少行能在原稿里逐字找到、原稿有多少行进了书。两个数字都摆出来，不替你判定。

## 一、句子有功能，别写成一种

一条条目里的句子通常是下面八类之一。写出分类意识，就不会把「可能」写成「必然」，也不会把作者的旁白塞进世界事实。

| 功能 | 例句形态 | 注意 |
|---|---|---|
| 世界事实 | 「渡口的浮桥每年霜降后拆」 | 可查证，不随场景变 |
| 因果 | 「矿脉断了，所以铁价三年翻了两番」 | 因果链要能推到玩家可行动的点 |
| 条件规则 | 「除非持有引水令，否则进不了闸区」 | 例外与条件必须一起写 |
| 倾向 | 「市面上多数船工不接夜活」 | 允许例外，别升格成规则 |
| 传闻 | 「有人说闸门下面是空的」 | 真假未定时不许替它定案 |
| 表达指令 | 「写到闸区时用短句、少比喻」 | 这是写给模型的，不是世界知识 |
| 当前状态 | 「此刻闸区闭锁」 | 会过期——归开场或状态层，见下 |
| 知识边界 | 「只有巡夜人知道换岗时辰」 | 说的是谁不知道，不是世界怎样 |

**最容易塌缩的两类**：「倾向」被写成「规则」（多数 → 一律），「传闻」被写成「事实」（有人说 → 确实是）。两处塌缩都会让模型再也演不出「不确定」。

## 二、五档强度，别混用

| 档 | 含义 | 写法 |
|---|---|---|
| **硬事实** | 不会因为场景或选择改变 | 直陈句，可以给数值 |
| **条件规则** | 在给定条件下成立，含例外 | 「若…则…」「除…之外」「只有在…时」 |
| **倾向** | 通常/多数/罕见，允许例外 | 带程度词，不写「总是」 |
| **自由空间** | 模型可以补，补了不算改设定 | 明写「可自由补充：…」 |
| **未决** | 谁来决定、何时定 | 「由用户决定」「留待剧情揭示」 |

两句话：「必须」和「通常」承诺的东西完全不同；写出「未决」比编一个答案更值钱——编出来的细节会在第三轮跟别处打架。

**否定要连条件一起保留。** 「护障挡住箭矢，但声音能穿过」不能简化成「护障隔绝外界」——后者顺手抹掉了它最有趣的那条缝。

---

## 三、名字不是定义

标签只提供称呼，**局部定义**才提供约束：这个名在本设定里指什么、不指什么、边界在哪。

- 「引水令」这个词本身不说明它长什么样、谁能发、能不能伪造。
- 同一名字在不同势力口中可能指不同的东西——那就分开写两条，注明「在 X 口中指…」。
- 一名多义、多名一义都不要合并；合并等于替世界做了一次它没做过的决定。
- 「模型应该懂」不是删掉约束的理由。作者想保留的事实要写出来，不能靠模型的常识兜。

---

## 四、知识边界：谁知道、知道多少、凭什么

客观事实、接触渠道、个人信念是三件事，别压成一件。

每条重要信息问四个问题：

1. **谁知道**：全部人 / 某势力 / 某几个人 / 无人？
2. **知道到什么程度**：未知 / 听说 / 部分 / 详细 / 记错 / 过期？
3. **依据是什么**：亲眼观察 / 文书 / 传闻 / 推断？
4. **什么新证据会改变它**：见到实物 / 拿到账本 / 有人当面否认？

写法示例：「船工知道闸区闭锁，但不知道闭到何时（听说，来源是巡夜的酒后话）」——一句话同时交代了范围、程度、依据。这类句子能让 NPC 自然地「知道一半」。

**作者知道 ≠ 角色知道。** 条目里写「闸门后面是空的」是给模型的资料；要让它只对某人有约束，必须另写一条知识边界，否则所有角色都会突然知道。

---

## 五、传闻与矛盾：两样都留着

- 传闻存在（有人这么说）是事实；传闻内容是否为真是另一件事。真假未定时，改写不许顺手定案。
- 世界里的矛盾常常是设定本身（两派记载不同），不是待修的错。保留矛盾并标明「两说并存，取决于…」，比统一口径更可玩。
- 缺的部分不补写。留白写成「未决」或「自由空间」，别用合理推测填空——推测写进正文就变成了约束。

---

## 六、当前状态不进设定

会过期的东西：位置、进行中的任务、暂时的伤势、此刻的情绪起点、本轮的门是否开着。它们属于开场（第一楼）或状态层（MVU / 标签）。

判据：**这句话下一轮还成立吗？** 不成立就不该写进常驻条目。写进常驻的代价是：第一轮之后，条目与世界自相矛盾，而条目还在每轮被注入。

---

## 七、改稿前后比对：语义不变量

改一条已有条目（或把论文式设定改成条目式）之后，逐条比对**意义**而不是字数：

- [ ] 覆盖范围没变：说的是谁、什么、哪些情况
- [ ] 前置条件、否定、代价、例外、因果链都还在
- [ ] 「通常 / 可能 / 罕见」没被改成「一律」，也没反向升格
- [ ] 事实 / 信念 / 接触渠道 / 时间 / 当前状态仍分得清
- [ ] 没有凭空多出能力、设定、目标、事件，也没有替玩家写动作
- [ ] 专名、宏、受保护语法（`{{user}}`、outlet 名、界面标签）一字未动
- [ ] 删掉的部分确实是冗余，不是「读起来不顺」的约束

---

## 八、表达指令写清六件事

写给模型的风格要求（放进条目或 `frontend-prompt.yaml`）要交代：

1. **要的结果**：短句？少比喻？只写动作不写心理？
2. **作用对象**：整段叙事、只有对白、还是只有状态栏文案？
3. **影响哪一层输出**：正文 / 提示词 / 界面
4. **强度**：必须 / 尽量 / 避免
5. **语义边界**：允许什么、禁止什么（给反面例子）
6. **已知例外与优先级**：与哪条冲突时以谁为准

「风格要冷一点」不是指令，是愿望；「不写内心独白，情绪只通过动作与停顿体现」才是指令。

---

## 九、三条常见死法与改法

**① 设定当文案写。** 「这座城有着悠久而复杂的历史，见证了无数兴衰」——没有一个可行动的点。改成能落地的：「城里三条引水渠，只有东渠还通水；巡夜人按渠段分班」。判据：这句话能不能推出一个玩家可以做的事。

**② 规则写成愿望。** 「守卫对陌生人保持警惕」——模型只能演成「看起来警惕」。改成条件规则：「守卫见陌生人先问来意；答不上来就带到闸房登记」。判据：能不能被外部观察到。

**③ 知识写成常识。** 所有人都知道密室位置，剧情就没有发现。给每条秘密配一条知识边界，再让渠道决定谁知道。

## 十、收笔自查

- [ ] 每条条目开头一句说清「这条讲什么」，不靠标题猜
- [ ] 硬事实有条件、倾向有程度词、传闻没有定案
- [ ] 至少有一条知识边界，而不是所有人共享全知
- [ ] 没有会过期的当前状态
- [ ] 名字都有一句局部定义，或明确「未定义」
- [ ] 没有替玩家写动作、感受、决定
- [ ] 条目长度在预算内（切法与关键词回 `references/worldbook-tuning.md`）

## 十二、分档设定：用「状态词」当关键词

想让设定随剧情推进换档（好感度到 60 才解锁亲密描写、潮压过 80 才出现溃堤剧情），不用递归、也不用另建世界书：**让前面的产物把档位写成聊天里看得见的字，再拿它当关键词**。

做法：

1. 轴或状态栏每轮输出一个格式稳定的阶段词，例如 `潮压:82`、`好感 61`。
2. 每个档位一条绿灯条目，关键词就写阶段串的前缀：`潮压:8`、`潮压:9`。
3. 条目放 `position: 0` 或 `1`，`excludeRecursion: true`，别设 `sticky`——档位靠状态词自己维持，加 sticky 会让旧档位赖着不走。

代价（必须一起写进交付说明）：

- **格式一改就失配**。阶段词的长度、分隔符、单位全是耦合点，改状态栏就等于改世界书关键词。
- 字符串包含不是数值比较。想表达「≥80」得把 `8x` 与 `9x` 两段都列上，或直接写正则 key：`/潮压:\s*(?:8[0-9]|9[0-9]|100)/`。正则更稳但可读性差。

## 附：资料库式（条目是数据行，不是设定段落）

条目数上百时，别再往关键词上堆——把条目当**数据库的行**：全部 `disable: true`（不参与扫描），命名统一成 `[data]<类>·<范围>`（`[data]人物资料·尾张`、`[data]城池资料·美浓`），由一条常驻控制器按状态 `getwi()` 取用。

写作方式随之变三条：

1. **每条只写一个对象**，节标题就是它的主键（原稿怎么分节，切割器就怎么切）。
2. **条目之间不互相解释**。控制器一次只取一组，跨组引用等于要求模型自己拼——拼错比不知道更糟。
3. **控制器是唯一读得懂"什么时候"的地方**。它读什么变量、分几组、默认取哪一组，要能在交付说明里一句话讲清；讲不清就是还没设计好。

什么时候值得换：条目 ≲60 用关键词；60 往上先是 `order` 分档（做法③），再往上只有这条路。判断依据不是"条目多"，是**"模型该看到哪几条"能不能由一个变量说清**——说得清就走资料库，说不清就说明这个世界还没被抽象成状态。
