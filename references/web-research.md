# 主动联网检索

`contract.project.web_research: true` 时全程生效：**每次动手写之前先检索，检索完才落笔**——世界观、角色卡、场景卡、数值系统，以及任何局部修改、补充、定名，一律先查。不是"需要时查一下"，是默认动作。

开关一开就别再问用户"要不要查""查哪方面"，也不再确认方向：**查什么由当前要写的内容自己判断**。

`web_research: false` 时跳过本文件，一切照常，也不许顺手搜。

开关只由用户决定，不由 AI 猜。用户说"不用查了"→ 关掉默认动作，`decisions` 记一条，改回问用户。

## 一、什么时候检索

| 时机 | 查什么 |
|---|---|
| 每阶段进入条件满足后、第一句追问之前 | 本阶段要用到的外部事实底盘（见下"查什么"） |
| 用户提到一个外部专名（人名/地名/组织/道具/事件/作品） | 这个名字的准确写法、指代对象、是否有译名分歧 |
| 要写角色卡 | 该角色（若来自已有作品）的官方设定、正式关系、说话习惯、退场状态、圈内高频 OOC 点 |
| 要写场景卡 | 该地点的地理、进入条件、真实或原作里发生过什么、是否已毁 |
| 要定数值/轴线 | 有无官方或圈内通行的数值口径（战力分级、好感度习惯） |
| 每次交付前 | 复核一遍本份产物里出现的外部专名，逐个确认没写错、没张冠李戴 |

**查什么**由内容自己判断，按项目类型分：

- 基于已有作品（同人/改编）：原作硬设定、术语与专名、时间线锚点、跨版本差异。
- 历史或真实地点：年代、地理、制度、称谓、常见史实错误。
- 专业领域（医学/法律/军事/工艺）：术语、流程、量级、物理与时代上限。
- 用户提供的自造设定：不用查，以用户口径为准。

**逐阶段的最低检索量**（开了开关就按这个做，不是想起来才查）：

| 阶段 | 动笔前至少查 | 落条 |
|---|---|---|
| 1 世界观 | 1 次底盘（题材通识 / 年代与地理 / 原作硬设定），≥3 条来源 | ≥3 条 |
| 2 角色卡 | 每个主要角色 1 次（身份对应的职业与年代细节 / 原作设定与 OOC 高频点），≥2 条来源 | 每人 ≥1 条 |
| 3 场景卡 | 每个地点 1 次（真实地点结构 / 原作里是否已毁 / 通行尺寸），≥2 条来源 | 每地 ≥1 条 |
| 4 数值系统 | 1 次（是否有官方或圈内通行的量级口径） | ≥1 条（查不到就写"无通行口径，自定为…"） |
| 5 / 6 前端 | 1 次（酒馆版本 / 插件版本的接口差异），有官方文档就查 | ≥1 条 |
| 7 交付 | 复核卡里所有外部专名，不再新查 | 复核记录 1 条 |

判据很硬：**进入某阶段后 `检索来源.md` 没有新增条目，这个阶段就不许交付**。因为"我判断不需要查"和"我忘了查"在产物上长得一模一样，只有记录能把它们分开。

同一事实不要重复检索；已在 `制作文件/项目记录/检索来源.md` 里记过的，直接引用记录，不再查第二遍。

## 二、怎么记

检索结果写进 `制作文件/项目记录/检索来源.md`（骨架 `templates/research-log.md`），一条一录：

```
- [S03] 来源：<站点/页面标题> · <URL> · 取用：<一句话说从这条取了什么>
       可信度：官方 / 权威资料 / 圈内通行 / 单一出处 / 存疑
       影响：<写进了哪份产物的哪个字段，或"仅参考未采纳">
```

规则：

- **一条记录只对应一个事实**，别把整页内容糊成一条。
- 没检索到就记 `未检索到`，并写下一步怎么补（问用户 / 标 `[推断：…](待确认)`）。不许静默跳过。
- 检索记录是 `制作文件/` 里的过程物，**不进导入包**，也不进 `contract.artifacts`。

## 三、冲突怎么裁

优先级从高到低：

1. 用户明确指定的口径（含"我要 AU，这里的 XX 不一样"）
2. 官方设定 / 权威资料（原作正文、官方设定集、作者公告、史料、专业文献）
3. 圈内通行设定（多来源一致的同人共识）
4. 单一出处 / 存疑来源
5. AI 推断（必须标 `[推断：…](待确认)`）

同级冲突、或 2 与 1 撞车时，停下问用户一句（带建议）。**不自行调和**——"我就要这个不一样"是常态，不是矛盾。

## 四、写进产物时的规矩

- 差异要显式化：与外部事实不一致的地方，在字段里写清依据（"用户指定：此处 XX 已死" / "AU 设定：忽略原作第 N 卷"），别让后来的 AI 以为是写错。
- 不复制原文：只取设定摘要、专名、关系、量级，**不搬原文段落**。一句原文式的描写都不要进产物。
- 不确定的专名先问再写，宁可标 `[待定：<哪个名字>]`，也不猜一个看起来像的名字。
- 命名门照常：外部专名进 `contract.naming`，与自创名字同等待遇。

## 五、没有联网能力时

先确认工具是否可用（有 web 检索/抓取工具就用）。用不了就：

1. 一句话告知用户"本次没有联网，外部事实靠你确认"，不要假装查过。
2. 走降级：把该阶段要用的外部事实列成一张 ≤8 条的确认清单，交用户勾/改。
3. 未确认的条目按 `[推断：…](待确认)` 写，并在 `创作记录.md` 记一条卡点。

**绝不编造外部事实**——编错一个专名或一个年代，整份产物都要返工。

## 六、别越界

- 检索是为了准确，不是为了扩写：查到十条只写用得上的三条。
- 不主动检索作品结局/关键反转去"提前告知"用户可能被剧透的内容；用户没提的情节不要拿来当卖点。
- 同人项目不把检索所得原作文本写进产物，只取摘要。
- 用户说"我熟，别搜了" → 见文首的关闭规则。
