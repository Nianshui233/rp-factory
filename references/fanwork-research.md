# 同人向 · 主动联网检索

`contract.project.fanwork: true` 时全程生效：**每一轮开始前先检索，检索完才落笔**。不是"需要时查一下"，是默认动作。

原创项目（`fanwork: false`）跳过本文件，一切照常。

## 一、什么时候检索

| 时机 | 查什么 |
|---|---|
| 每阶段进入条件满足后、第一句追问之前 | 该阶段要用到的原作硬底：基础设定、术语、时间线锚点 |
| 用户提到一个原作专名（人名/地名/组织/道具/事件） | 这个名字的准确写法、指代对象、是否有官方译名分歧 |
| 要写角色卡 | 该角色的官方设定、正式关系、说话习惯、已故/退场状态、圈内高频 OOC 点 |
| 要写场景卡 | 该地点的地理、进入条件、原作里在此发生过什么、是否已毁 |
| 要定数值/轴线 | 原作有没有官方或圈内通行的数值口径（战力分级、好感度习惯） |
| 每次交付前 | 复核一遍本份产物里出现的所有原作专名，逐个确认没写错、没张冠李戴 |

同一事实不要重复检索；已在 `创作痕迹/检索来源.md` 里记过的，直接引用记录，不再查第二遍。

## 二、怎么记

检索结果写进 `创作痕迹/检索来源.md`（骨架 `templates/research-log.md`），一条一录：

```
- [S03] 来源：<站点/页面标题> · <URL> · 取用：<一句话说从这条取了什么>
       可信度：官方 / 授权 / 圈内通行 / 单一出处 / 存疑
       影响：<写进了哪份产物的哪个字段，或"仅参考未采纳">
```

规则：

- **一条记录只对应一个事实**，别把整页内容糊成一条。
- 没检索到就记 `未检索到`，并写下一步怎么补（问用户 / 标 `[推断：…](待确认)`）。不许静默跳过。
- 检索记录是 `创作痕迹/` 里的过程物，**不进最终产物**，也不进 `contract.artifacts`。

## 三、冲突怎么裁

优先级从高到低：

1. 用户明确指定的口径（含"我要 AU，这里的 XX 不一样"）
2. 官方设定（原作正文、官方设定集、作者公告）
3. 圈内通行设定（多来源一致的同人共识）
4. 单一出处 / 存疑来源
5. AI 推断（必须标 `[推断：…](待确认)`）

同级冲突、或 2 与 1 撞车时，停下问用户一句（带建议）。**不自行调和**——同人项目里"我就要这个不一样"是常态，不是矛盾。

## 四、写进产物时的规矩

- 差异要显式化：与官方不一致的地方，在字段里写清依据（"用户指定：此处 XX 已死" / "AU 设定：忽略原作第 N 卷"），别让后来的 AI 以为是写错。
- 不复制原文：只取设定摘要、专名、关系，**不搬原作段落**。一句原文式的描写都不要进产物。
- 不确定的专名先问再写，宁可标 `[待定：<哪个名字>]`，也不猜一个看起来像的名字。
- 命名门照常：原作专名进 `contract.naming`，与自创名字同等待遇。

## 五、没有联网能力时

先确认工具是否可用（有 web 检索/抓取工具就用）。用不了就：

1. 一句话告知用户"本次没有联网，原作细节靠你确认"，不要假装查过。
2. 走降级：把该阶段要用的原作事实列成一张 ≤8 条的确认清单，交用户勾/改。
3. 未确认的条目按 `[推断：…](待确认)` 写，并在 `创作记录.md` 记一条卡点。

**绝不编造原作设定**——同人项目里编错一个专名，整份产物都要返工。

## 六、别越界

- 检索是为了准确，不是为了扩写：查到十条只写用得上的三条。
- 不主动检索原作结局/关键反转去"提前告知"用户可能被剧透的内容；用户没提的情节不要拿来当卖点。
- 用户说不必查（"我熟，别搜了"）→ 关掉本文件的默认动作，改回问用户；`decisions` 记一条。
