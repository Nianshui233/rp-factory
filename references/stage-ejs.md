# 阶段 `ejs` · 分档控制器（EJS）

产物 type：`ejs-controller`。骨架：`templates/ejs-controller.ejs`。格式与降级链回 `references/interview-protocol.md`。

## 进入条件

- 需要酒馆助手 **Prompt Template（ST-Prompt-Template）**。没装 → 说明"这条要有 EJS 渲染，没装控制器只会显示成一个代码块"，本阶段 `skipped`。
- 有 `axis-system.yaml` 才能做**有变量的**控制器；没有轴也可以做"按条件切条目"（`getwi` 用别的判据），但要在 `decisions` 写清判据从哪来。
- 有 `cast` / `scenes` 产出的、可以拆成分档的条目（本阶段**只改写**，不新写人设正文）。
- `project.web_research: true`：先查过 EJS 现行语法与限制再动笔，记 `创作痕迹/检索来源.md`。
- 用户明说"分档人设 / 按数值换人设 / 到某档就换一套说法"才进；只说"报一下当前档位"不进（见下）。

## 追问

**先判断该不该做**（判断标准第一条），该做再问，**最多 2 轮、每轮 ≤4 问**：

| 问题 | 选项 | 落进 |
|---|---|---|
| 控制器切什么 | A 人设 / 称谓 / B 场景可见细节 / C 两样都要（两个控制器） | 控制器数量 |
| 阶段边界 | A 用轴的 `thresholds` 原值 / B 自己定 3–5 档 | `阶段边界` |
| 被控条目怎么来 | A 从已有条目改写（默认）/ B 新写 | `改写清单` |
| 无 MVU 时怎么办 | A 不做（默认）/ B 用 `[InitialVariables]` + 模型自己写 `setvar`（可靠性低一档） | `mode` |

## 判断标准

### 什么时候不做

**只有一条判据**：这份内容如果**整段再写一份进世界书**，会不会**几份全部同时进上下文**？

- 会 → 值得建控制器（控制器只加载命中那一份，其余留 `disable: true` 不进上下文）。
- 不会（内容很短、本来就该整段常驻）→ **不建**。典型反例：只是把当前档位名字报出来。书里已经有阈值表与行为描述时，那句"当前是第 3 档"是冗余的——实验里被控条目一字未改，行为却已经跟着数值走了，功劳在阈值表，不在控制器。
- 不建就 `skipped`，`decisions` 记一句"轴表已够，不建控制器"。

### 控制器只做切换

- 控制器本身很短：读变量、按边界分叉、每个分叉一行 `await getwi`。
- 内容全在被控条目里；被控条目 `disable: true`（否则它们会跟着控制器一起常驻，等于白拆）。
- 不改人设事实：只改"这一档用什么口径说话 / 什么细节可见"。改事实要回 `cast` 阶段。

### 语法四条（写错就整段不渲染）

```ejs
<%_ if (typeof tier === 'undefined') var tier = getvar('stat_data.角色.祁昭.灯芯', { defaults: 0 }); _%>
<%_ if (tier >= 70) { _%>
<%- await getwi(null, '[阶段]祁昭·满灯') %>
<%_ } else if (tier >= 30) { _%>
<%- await getwi(null, '[阶段]祁昭·半灯') %>
<%_ } else { _%>
<%- await getwi(null, '[阶段]祁昭·残灯') %>
<%_ } _%>
```

1. **只用 `<%_ … _%>`**（带下划线，吃掉换行）。`<% ` 与 `<%=` 会留下空行，一多就撑爆上下文。
2. **每个变量都要 `typeof` 守卫 + `var`**：`typeof x === 'undefined'` 防止同名变量在多次渲染间重复声明（`let`/`const` 会直接抛 `Identifier has already been declared`）。
3. **`getvar` 路径以 `stat_data.` 开头**：EJS 的变量表是由 MVU 写进楼层的那份合并来的，路径漏了前缀读到的就是 `undefined`。没有 MVU 时用 `initial.` 前缀。
4. **`getwi` 必须 `await`**，条目名逐字一致；被控条目必须 `disable: true`。

### 边界必须无缝且不重合

- 分支链按数值升序写，相邻两档"上界 + 1 == 下界"，不许留缝（`> 30 && < 70` 就把 30 与 70 丢了）。
- 末档允许 `else` 兜底；也允许写成 `<= 100`。**两种都合法**，别为了"看起来严格"把 `else` 改掉。
- 档数 3–5 档最稳；超过 6 档时先问是不是该合并——太多档位更像状态栏的活。

### 能力边界（超出就退回静态分档）

能做：按数值分叉、按字符串比较切条目、`getwi` 装载条目、读 `stat_data` 任意字段。
不能做：`JSON.parse`、复杂数组运算、网络请求、定时任务、`eval`、字符串方法以外的处理。越界就退回静态分档，在 `decisions` 记一笔。

## 生成

**Step 1 · 定档位**：从 `axis-system.yaml` 的 `thresholds.<轴>.levels` 取边界，或按追问结果自定 3–5 档。写出"档名 ↔ 上下界"的对照表。

**Step 2 · 写控制器**（`templates/ejs-controller.ejs`）：文件头注释写死"被控条目必须 `disable: true`、本条目 `constant` + `after_char` + `order 100` + 递归双向 prevent"。

**Step 3 · 改写被控条目**：从已有条目拆/改称谓/只加 `disable`，**不改事实**。整份世界书改写前先备份到 `创作痕迹/产物/改写前/`。

**Step 4 · 写改写清单**：`创作痕迹/产物/ejs/改写清单.yaml`，每条记 `条目名` / `改动类型`（拆分·合并·改称谓·只加禁用）/ `改前字数` / `改后字数`。改名或拆条导致的下游引用，一并回写。

**Step 5 · 边界用例**：在控制器同目录写 `边界用例.md`，取每档边界的 ±1（如 59 / 60 / 30 / 29），逐个写"命中哪一档"，跑校验器核。

**Step 6 · 校验**：`python scripts/validate-ejs.py 创作痕迹/产物/ejs/阶段控制器.ejs --book <世界书>`。

## 写回契约

- `stages.ejs` → `partial` / `done` / `skipped`。
- `artifacts[]`：`type: ejs-controller`，`path: 创作痕迹/产物/ejs/阶段控制器.ejs`；改写清单同目录，不单独记 artifact。
- `decisions[]`：不建控制器的理由（若跳过）、档位怎么定、被控条目改了哪几条。
- `hard_settings[]`：不新增（分档边界的权威在 `axis-system.yaml`，这里只是复述）。

## 退出

- 变量门：`validate-ejs.py` E01–E08 全过、退出码 0。
- 命名门：控制器里的条目名、轴名与 `naming` 一致；`getvar` 路径里的角色键与角色卡一致。
- 交付说明里三句：① 被控条目已设为禁用；② 控制器条目要 `constant` 才每轮生效；③ 没装 Prompt Template 时这段会显示成代码块。
- 被控条目若改了名，确认 `改写清单.yaml` 与 `decisions` 都写到，且旧名在下游产物里没有残留。
