# 阶段 3 · 场景卡

产物 type：`scene-sheet`。骨架：`templates/scene-sheet.yaml`（根键 = 具体场景名）。格式与降级链回 `references/interview-protocol.md`。

## 进入条件

- 有 `contract.naming.world`：读硬规则、常识、科技/魔法上限、势力结构、禁忌边界，**不得写出与之冲突的内容**。同时读 `naming.places[]`，场景落在已有地点上就不新建地点。
- 无 `naming.world`：触发一次补采访问（≤3 问，只问影响场景可判定性的项——世界有无超常力量、社会秩序大致形态、技术上限）。问不到才写 `[待定：…]`。
- 用户直接给出地点构想：可直接进追问，但上面那次补采访问照做。
- 用户提交已有场景卡 + 修改需求：走迭代，不重走采集。
- `project.web_research: true`：先按 `references/web-research.md` 检索该地点的地理、进入条件、真实或原作里发生过什么，记进 `创作痕迹/检索来源.md`，查完才动笔。

**细节深度按玩法定**：

| 玩法导向 | 结构强度 | 必须写到的块 |
|---|---|---|
| 日常 / 对话 | 轻结构（关键区域 + 氛围 + NPC） | `概览` / `关键区域` / `生态` / `边界` |
| 潜入 / 推理 / 战术 / 密室 | 强结构（出入口、拓扑、门禁、巡逻、线索分布、时间表） | 全部十块，尤其 `空间结构` / `出入口与安防` / `线索` / `时间与事件` |

## 追问

**首轮 ≤10 问**，覆盖：场景类型、规模、玩法重心（日常/潜入/推理/战术）、危险度、是否需要地图级结构。内容边界已在开局四问锁过，不重复问；场景若涉及越界元素（`nsfw: false` 时的性内容、`hard_no` 里的任何一条），直接指出并给替代方案。

**后续每轮 ≤8 问**，聚焦缺失项。

**流程四步**：① 首轮提问确认用途与边界 ② 出粗版场景卡（允许留空或给 A/B/C 选项）并标缺失信息 ③ 对缺失项继续提问补全 ④ 用户确认后出终稿。

**粗版允许**：留空、给选项、局部只写骨架。**不允许**：把关键硬规则当既定事实写死（那是替用户拍板）。

## 判断标准

**四条可判定性要求**

1. **可判定性**：任何会影响行动选择的要素——距离、通路、权限、风险、代价、可观察性——必须能被明确判断。写"戒备森严"不可判定，写"正门2人巡逻、换岗间隔20分钟、监控覆盖大堂与楼梯口"可判定。
2. **可扩展性**：允许"未列出的区域"按 `关键区域 > 其他未命名区域的生成规则` 补全，不一次性写死全部细节。
3. **不得越权写死**：世界硬规则优先。场景里要打破世界规则（如反魔力场），必须写进 `规则 > 特殊规则` 并说明来源，不能默认存在。
4. **对齐世界锚点**：`概览 > 所属地域与世界观锚点` 必须能对上契约里的 `places[]` 或 `factions[]`；对不上说明场景凭空长出来的，回去补采。

**内容标准**

- `关键区域` 建议 5–12 个；少于 5 个的强结构场景说明拓扑没拆开。
- 每个区域五项写全：功能、现场可见（默认信息）、可互动点、风险与限制、连接到。缺"风险与限制"的区域等于没有张力。
- `线索` 至少 3 条，每条含"可能误导"——没有误导项的线索是答案不是线索。
- `时间与事件 > 必然事件` 的触发条件必须明确，不允许"剧情需要时发生"。
- `边界 > 不允许出现的剧情走向与元素` 必须与 `content_boundaries.hard_no` 一致。

## 生成

1. 按 `templates/scene-sheet.yaml` 填写十块：`概览` / `空间结构` / `关键区域` / `出入口与安防` / `生态` / `资源与可破坏物` / `线索` / `时间与事件` / `规则` / `边界`。
2. 不适用的块整段移除（如纯野外场景可去 `出入口与安防` 的门禁体系），不留 `[不适用]` 残迹。
3. 深度不够的块不强行填满：留 `[待定：…]` 并登记到契约 `pending`。
4. 渲染按 `references/dual-mode.md`：文本模态一个 yaml 代码块、块外无字；工程模态写 `创作痕迹/产物/scene-sheet.yaml`。

**字段转写对应**（写模板时的口径，不是让你复用旧格式）：原"标题 + 加粗字段"逐项变成 `字段: ""`；原缩进子弹列表变成该键下的 list 或 object；原括号提示移到 `#` 注释；结构位留空字符串。

## 写回契约

- `naming.places[]` 追加本场景 `{id, name, scope}`。场景已存在则更新 `scope`，不新建重复项。
- 场景引入新势力：走冲突规则——问用户是否加进 `naming.factions[]`，不许静默新增。
- `stages.3` → `partial` / `done`。
- `hard_settings[]`：用户在场景层确认的空间事实（"只有一个消防通道"这类）追加，`source: 用户确认`。
- `pending[]`：所有 `[待定：…]` 登记。
- `content_boundaries` 未锁定 → 不落笔，先回边界门。

## 退出

- 自检门四类通过（内容边界层那一类仅当 `content_boundaries.nsfw: true` 且本场景确实涉及性内容时执行）。
- 命名门四步通过：场景名、区域名、势力名、地点 id 与契约一致。
- 交付形态：**只交付场景卡本体，除模版本体不附加任何内容**；一个 yaml 代码块。需要说明的补全项与待定项放在代码块外（文本模态）或交付消息里（工程模态）。
- 交付后回写契约 → **阶段收尾一检** `python scripts/check-stage.py scenes <项目根>`（内部查契约），退出码 0 → 阶段结束。
