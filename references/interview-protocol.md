# 追问协议

每个阶段的首轮与后续轮都用同一套格式。阶段文件只声明"首轮问几个、必问哪几项"，格式与降级链一律回本文件。

## 一、问题块格式

一个问题就是下面五段，缺一不可：

```
【问题 N】<一句话问题，具体到当前项目，不空问>
- A：<选 A 之后世界/角色会变成什么样>
- B：<选 B 之后会变成什么样>
- C：<选 C 之后会变成什么样>
- 我的建议：A
  为什么：<基于哪条已锁定设定，或哪条判断标准>
  影响：选 A 则 <下游哪个产物会变>；选 B 则 <下游哪个产物会变>
```

硬规则：

- 每题 2–3 个选项，用户可以说"其他"。
- **禁止开放式空问**（"你觉得这个角色怎么样？""想要什么风格？"）。
- **"我的建议 / 为什么 / 影响"三行不可省。** 原文只要求给 2–3 个选项；本包在此基础上要求给出建议与其后果，让用户在不知道答案时也能选。
- 选项描述写后果，不写标签。"黑暗"不合格，"整体黑暗但允许局部温情，代价是喜剧桥段会被压掉"合格。
- 一轮里问题数不超过该阶段的预算（见第二节）。超了就把次要的降级为 `[推断：…](待确认)`。

## 二、预算表

**开局四问不占阶段预算**：工作区、阶段多选、是否启用 NSFW、是否需要联网一次问完，用结构化选项，不用第一节的问题块格式。

| 阶段 | 首轮上限 | 后续每轮上限 | 轮数上限 |
|---|---|---|---|
| 0 `start` 开工判定 | 0 问（并入开局四问） | — | — |
| `world` 世界观 | 5–7 | 8 | 无限，收敛门通过即提议出终稿 |
| `cast` 角色卡 | 3 | 3 | 2 |
| `scenes` 场景卡 | 10 | 8 | 无限 |
| `axes` 数值系统 | 4 | 4 | 2 |
| `mvu` 变量系统 | 5 | 5 | 2 |
| `ejs` 分档控制器 | 4 | 4 | 2 |
| `opening` 开局前端 | 3 | 3 | 2 |
| `statusbar` 状态栏前端 | 3 | 3 | 2 |
| `delivery` 交付 | 1（只问路线） | 0 | 1 |

`delivery` 那 1 问不占其他阶段预算，也不套问题块：给三个选项（原生 / 酒馆包 / 两者都要）即可，不用写「我的建议」三行——它不改变作品走向，只决定出包形式。

`start` 不单独提问：工作区、阶段、NSFW、联网已在开局四问里定完；题材与 RP 形式并入阶段 1 首轮。用户一开口就点名某个产物时，同理直接从该阶段首轮问起。

## 三、补采访问

任选阶段发现上游契约项缺失、且该缺失会破坏本阶段的可判定性时，允许发起**一次**补采访问：≤3 问、计入本轮预算、只问影响可判定性的项。

问不到才写 `[待定：<缺什么>]`。不许一发现缺上游就直接把整份产物铺成待定。

用户沉默的三种处理（没看到 / 不想定 / 答不了）与「未答不是委托」见 `references/decisions.md` 第三节；记进契约的是 `decisions[].state`。

三个典型触发：

| 场景 | 缺什么 | 问什么 |
|---|---|---|
| 用户直接要场景卡，没有世界观 | `naming.world`、`naming.factions` | 这是什么世界、有哪几方势力在争这块地方 |
| 用户直接要角色卡，没有世界观 | `naming.systems`（超自然/科技上限） | 这个人所处的世界有没有超常力量，上限到哪 |
| 用户直接要数值系统，没说怎么玩 | `project.rp_form` | 1v1 长线、多人局、还是一次性短局 |

## 四、降级链

按顺序执行，前一步失败才进下一步：

1. **追问**。按预算提问。
2. **给两组对比设定**。追问无果时，在用户未明确的那一维上构造 A / B 两组，已明确的维度保持一致，让用户二选一。两组都要附「我的建议」与理由。
3. **用户说"你来定"**：自主补全，逐项标 `【AI补全·可替换】`，不留 `【未知】`。
4. **用户仍无有效回应**：采用通用假设 + 标 `【AI补全·可替换】` + 末尾一句假设说明（不超过两句，说清假设了什么、会影响哪里）。

降级链的每一步都要落进 `contract.decisions`：用了哪一步、假设了什么。

## 五、痕迹记录（创作记录.md）

工程模态下，每轮访谈结束追写 `<项目>/制作文件/项目记录/创作记录.md`。**只记过程与结论，不存 YAML 草稿副本。**

固定四节，只追加不改写：

```markdown
## 阶段 2 · 第 1 轮（2026-11-20）

### 问了什么
- 角色名 / 核心动机 / 底线（3 问，符合阶段 2 首轮预算）

### 用户答了什么
- 角色名：“孙野”——理由是家里人叫他小野
- 动机：选了 B（找弟弟）
- 底线：“其他：他不杀人，包括报仇的时候”

### 我的建议与用户偏离点
- 建议 A（复仇），用户选 B（找人）——下游影响：`internal_conflict` 从“恨与怕”改成“找与放弃”

### 本轮落下什么
- `contract.decisions` +2 条；`stages.2: partial`；`制作文件/产物/rolecard/` 尚未写（本轮只采集）
```

追加规则：

- 每轮一节，带阶段号与轮次；跨天再加日期。
- “我的建议与用户偏离点”这一行不许省：它记录的是**为什么**，日后回看靠它才能理解当时的判断。
- 降级链走到第几步、假设了什么，写进本节，不另开文件。
- 不写草稿内容、不粘 YAML。用户要历史版本，交给 git。

文本模态下不建目录、不写 `创作记录.md`：只把决策写进 `contract.decisions`（若用户同意落一份契约）或只在会话里说。

## 六、什么时候停下来问，什么时候自己定

**必须问**：会改变世界走向的硬设定、命名（实体叫什么）、内容边界、已有产物的冲突。

**自己定并标注**：字段措辞、示例、结构排布、可合理推断的数值范围。

**自己定不标注**：格式、缩进、小节顺序这类实现细节。
