主 skill 与六个阶段文件都从本文件取名字。**这里定义的东西，别处只引用，不另造。**

## 二、占位符（只有 7 个）

| 占位符 | 用途 | 不许用的场合 |
|---|---|---|
| `【未知】` | 信息缺失且无法推断，且不影响可判定性 | 能靠补采访问到的；能合理推断的 |
| `【AI补全·可替换】` | 系统自主补全的内容，等用户确认 | 用户已明确说过的；会改变世界走向的硬设定（那种必须问） |
| `[待定]` | 粗版里尚未采集的模块 | 能推断的；能补采访问到的 |
| `[待定：<缺什么>]` | 同上，且指明缺哪项 | 同上 |
| `[推断：<内容>](待确认)` | 已给出内容但来源是推断，需用户点头 | 用户确认过的 |
| `[不适用]` | 该模块对本项目不成立 | 只是还没填的 |
| `[用户跳过]` | 用户明确表示暂不处理 | 用户只是没回答 |

七个以外的标记一律不用。`[不适用]` 的模块在终稿中整段移除，不留空壳。

## 三、九道门

**`开工门`（阶段 0）** 判"够不够开工"：能否定出目标阶段。不单独提问——题目并入下游首轮。

**`边界门`（任何产物落笔前）** 开局问完就能锁：`content_boundaries.nsfw` 定下开关，随之 `rating` 与 `hard_no` 锁定（`nsfw: false` 时 `hard_no` 至少含「任何性描写」）。开局没答 NSFW 的按「否」锁。阶段首轮不再问边界，只补开工时没问到的细节（≤2 题）。锁定前不产出任何设定正文。

**`收敛门`（仅阶段 1）** 同时满足以下全部才提议出终稿：所有关键系统具备"能/不能/代价/上限"四要素；判定框架已填；核心矛盾各方目标与手段明确；无未解决的致命或重要级缺口；硬设定已有 ≥3 条（计法：用户确认的、或用户明确委托决策后标 `【AI补全·可替换】` 且已告知的——委托不等于未定，但必须在末尾说明）；RP 常见场景覆盖验证基本通过。

**`自检门`（每份产物交付前，内部执行，不向用户展示）** 四类检查，见第四节。

**`命名门`（每次渲染产物前）** 四步，见第五节。

**`联网门`（仅 `project.web_research: true`）** 每次落笔前先检索（不限阶段，含局部改动），交付前复核一遍本份产物里的全部外部专名；每条检索记进 `创作痕迹/检索来源.md`，且进入本阶段后必须比之前多出至少 1 条——没有新增条目 = 没查，不许交付。逐阶段要查什么见 `references/web-research.md` 第一节的逐阶段检索量。没检索到就记 `未检索到` 并改走确认清单，不编造。细则见 `references/web-research.md`。

**`阶段门`（贯穿全程）** 一次只做一个阶段：做完就停，汇总本轮落下什么 + 哪些是替用户定的 + 下一步是哪一阶段，然后等用户回话。不许在同一条回复里连做两个阶段，不许交付后直接弹「继续吗」的选项。用户说「全流程」也只代表不用逐段问，不代表可以一口气做完。

**`交付门`（仅阶段 7）** 六条：两个 JSON 可解析且 `spec == "chara_card_v2"`；世界书条目 `content` 非空、`key` 是数组、`position` ∈ {0,1,4}、`uid` 连号；`data.extensions.world`、`st_name`、两个文件名四者同源；`first_mes` 里的标签能在某个正则的 `findRegex` 里找到，找不到就换普通开场白；`description` 里的实体名逐个能在 `naming` 找到；交付说明四步齐全且写明「内嵌正则要允许」。细则见 `references/stage-7-delivery.md`。

**`前端门`（仅阶段 5 / 6）** 八条：标签三处一致（正则 ↔ HTML 的 `TAG` ↔ `frontend-prompt.yaml`）、字段两处一致且能追到产物、`markdownOnly: true`、`replaceString` 的代码块含 `<body>`、数据路径自洽（走 `$1` 注入就必须有捕获组与隐藏 textarea，走静态或聊天 API 就必须都没有）、无外链无 `eval` 无 `document.write`、本楼无标签或占位符未被替换时留白不报错、脏值与越界值都安全。细则与机制事实见 `references/frontend-conventions.md`。

## 四、自检门四类

**逻辑一致性**
- 价值→行为推导：相邻价值之间的取舍，至少在 1 条行为规则里有体现
- 底线一致性：每条底线在"永不"清单中有对应条目
- 价值推导溯源：超出底线的"永不"条目，均可从价值排序推出
- 恐惧→压力反应：写下的恐惧在压力反应中有对应表现
- 内心冲突可见性：内心冲突在道德困境类规则中有体现
- 态度→行为一致：对各类人群的行为模式不与行为规则矛盾

**覆盖度**
- 场景覆盖：行为规则 ≥4 条，覆盖合作 / 冲突 / 压力 / 道德困境四类
- 语言印证：每条示例台词至少体现 1 条语言规则，整体符合语言风格
- 口头禅一致：口头禅用词符合语言风格的语气与词汇
- 压力语言一致：压力下的语言变化不违背语言规则

**内容边界层**（仅当该层存在时执行）
- 反差可信度：性格反差能从心理层找到依据
- 一致性：偏好不与行为模式矛盾

**格式**
- 无空泛形容词（不可观察的性格描述）
- 可观察特征 + 他人反应，两段都在
- 不确定处已标注占位符
- YAML 语法正确：列表用 `-`，键值用 `key: value`，缩进统一 2 空格
- 无空白占位字段（要么填内容，要么标占位符）
- 结构性键用英文，描述性内容跟随用户语言
- 终稿不含台账块：`元信息` 与 `类型与基调` 只在 `创作痕迹/项目档案.yaml`（见 `references/stage-1-world-bible.md` 生成节）

## 五、命名门四步

1. 从 `contract.naming` 取出全部名字：`world` / `factions[]` / `places[]` / `systems[]` / `axes[]`。
2. 对每份待交付产物做名字扫描：出现某实体但名字不匹配，或出现同义异名（"蚀月教团" vs "月蚀教"）→ 停下。
3. 有冲突：列出冲突双方所在产物 + 契约原始值，问用户保留哪个（一问，带建议）。
4. 用户选定后：改契约 → 回写所有已引用该名字的产物 → 记入 `contract.decisions`。

## 六、输出纪律

- 终稿只输出模板本体，不加前言、结语、"以下是……"。
- 移除全部 `#` 注释行与被注释掉的可选结构。
- 文本模态是一个 ```yaml 代码块；代码块之外只允许四样：设计说明（≤ 5 句）、补全清单、待确认清单、运行示例（仅数值系统）。
- 表现层例外（阶段 5 / 6）：交付三个代码块——完整 HTML、正则 JSON、提示词条目 YAML；HTML 必须在 ```html 块内，正则必须在 ```json 块内，不套 YAML 骨架。阶段 5 做建卡向导时，还要多一句操作说明（把触发词填进角色卡「第一条消息」）。
- `【AI补全·可替换】` 与 `[待定：…]` 保留在正文里，不在正文里夹解释。
- 交付前先过自检门，再过命名门，顺序不可颠倒。
- **交付后停住**：把产物、补全清单、待确认清单摆出来，写清下一步是哪一阶段，然后等用户回话。不在同一条回复里开启下一阶段，也不弹"要不要继续"的选项。
