# 双模态

同一份草稿，两种交付形态。默认 `mode: text`。

## 一、对照表

| | 文本模态 `text` | 工程模态 `engineering` |
|---|---|---|
| 交付 | 会话里一个 ```yaml 代码块，用户直接复制 | 文件写进 `<工作区>/<世界名>/创作痕迹/产物/` |
| 实现 | 无 | 该目录下四个文件：`world-bible.yaml` / `rolecard.yaml` / `scene-sheet.yaml` / `axis-system.yaml` |
| 附加 | 代码块外只允许设计说明、补全清单、待确认清单、运行示例 | 只在最后报「已写入哪些文件」，不重复贴正文 |
| 痕迹 | 不落盘 | 过程与结论写进 `<项目>/创作痕迹/创作记录.md` |
| 切换 | 默认 | 用户说「给我能粘贴的」「贴出来看看」时切回 |

## 二、切换规则

触发词：**「给我能粘贴的」** → text；**「存成文件」「放到项目里」「写进仓库」** → engineering。

- 切换**不重跑阶段**，只换渲染目标。已产出的内容不重新生成。
- 切换时把新值写回 `contract.project.mode`，并在 `contract.decisions` 记一条。
- 同一会话内可来回切；不因此产生第二份草稿。

## 三、渲染规则

**文本模态**
- 输出且仅输出一个 ```yaml 代码块，内容 = `templates/<type>.yaml` 填完后的结果。
- 不用 Markdown 表格，不用 `- **字段**：` 列表，不用 HTML 折叠块。
- 代码块之外只允许四样东西：设计说明（≤ 5 句）、`【AI补全·可替换】` 补全清单、`[待定：…]` 待确认清单、运行示例（仅数值系统，必须展示完整计算）。四样都没有就什么都不写。
- 不加开场白、不加结语、不解释自己写了什么。

**工程模态**
- 写到 `<工作区>/<世界名>/创作痕迹/产物/`，设定产物各一个文件。`最终产物/` 交付前保持空。目录结构与工作区确认流程见 `SKILL.md` 第二节。
- 文件名固定，不按项目改名。
- 写完后在 `contract.artifacts[]` 追加 `{type, path, version}`，`path` 用相对项目根的写法（如 `创作痕迹/产物/world-bible.yaml`）。
- 交付消息只报文件名与一句话摘要，不重复正文。
- 同时把这轮的访谈要点与决策追写到 `创作痕迹/创作记录.md`（格式见 `references/interview-protocol.md`）。
- **不往 `创作痕迹/` 里存 YAML 草稿副本**；版本回溯交给 git 或用户自己。

**两模态共用同一份草稿**，改一处不会出现两个版本。

## 四、表现层的例外

`opening` / `statusbar` 的产物不是 YAML 骨架，两模态只换交付方式，不换文件形态：

| | 文本模态 | 工程模态 |
|---|---|---|
| 开局前端 | 三个代码块：html / json / yaml 各一 | `创作痕迹/产物/opening-ui.html`（登场面板）或 `wizard-ui.html`（建卡向导）+ `regex-opening.json` + `frontend-prompt.yaml` |
| 状态栏前端 | 同上，换 statusbar 那三份 | 同名文件 |

- 三个代码块合并成一份 YAML 的想法不成立：HTML 与 JSON 必须能被 ST 直接导入/贴上，包进 YAML 字符串就多一道转换。
- 代码块外的四样附属说明照旧适用，但设计说明改成「机制说明」：正则怎么导入、渲染开关在哪、提示词条目贴哪里。

## 五、打包的例外

`delivery` 的 `st-card` / `st-worldbook` 是 JSON，不受 YAML 骨架约束：

| | 文本模态 | 工程模态 |
|---|---|---|
| 酒馆三件套 | 三个 ```json 代码块（卡 / 正则 / 世界书）+ 装配四步 | `最终产物/<世界名>（纯净）.json`、`正则.json`、`<世界名> 世界书.json` |

- 原生路线的 YAML / HTML / 正则 JSON 不被替换，两条路线并存。
- 用户说「只要粘贴版」→ 三个 JSON 代码块给全（卡 / 正则 / 世界书），契约里 `artifacts` 照记但 `pending` 标 `未落盘`。
- 打包不产生新设定：只重排已有产物，不得在这一步现编内容（现编就回对应阶段补）。

## 六、注释剥离规则

- `templates/*.yaml` **保留** `# 例：…` 注释，便于填写。
- 渲染前移除全部 `#` 注释行，以及被注释掉的可选结构。
- `[不适用]` 的模块**整段移除**，不留空壳、不留 `模块名: [不适用]` 这种残迹。
- 其余六个占位符按原样留在正文里，不在正文里夹解释。

## 七、选择建议

- 只想拿去聊 → `text`，交给用户复制进酒馆 / 任意前端。
- 想让产物成为可继续施工的资产（后续阶段要读它、要改名回写、要多人维护）→ `engineering`。
- 用户没说且看不出意图 → `text`，一句话告知可切。开局问工作区时用户已给了路径，按 `engineering` 走。
