# 阶段 5 · 开局前端

产物 type：`opening-ui`。机制、三条数据路径、HTML 骨架、正则格式、提示词条目全在 `references/frontend-conventions.md`——**进入本阶段先读它**，这里只补开局特有的东西。

**两种形态，由用户选，做完一种就算完成：**

| 形态 | 是什么 | 出口 |
|---|---|---|
| A 登场面板 | 开场画面：标题 + 一句基调 + 三处信息 + 2–3 个入口按钮 | 点入口 → 发一句话 → 进入正文 |
| B 建卡向导 | 多步表单：世界观序章 → 分组填角色 → 总览导出 | 复制一段「角色档案」→ 粘贴回聊天 → 交给阶段 2 |

用户说"开局界面/首页/开场画面"默认指 A；说"建卡/捏人/角色创建/填表"默认指 B；说不清就问一句（这是本阶段第一个问题，不是最后）。

## 进入条件

- 需要 `naming.world`；有 `创作痕迹/项目档案.yaml` 的 `类型与基调`（标题、基调词、类型）就直接取，不另起炉灶。
- 形态 B 还需要阶段 2 的字段规范（`references/stage-2-rolecard.md` 的规范 1–6）或已有 `rolecard.yaml`：向导的分组就是角色卡的字段分组，**字段名用角色卡的字段名**，别另造一套。
- 有 `axis-system.yaml` 时，向导的数值项（初始好感、初始灯芯之类）从轴的 `initial` 预填。
- 用户明说要"开局界面 / 开场面板 / 建卡向导 / 首页"才进。只说"美化一下"→ 问是开局还是每轮状态栏，别猜。
- `project.web_research: true`：界面里要出现真实地名、器物、专业术语时先查（`references/web-research.md`），纯虚构世界不查。
- 没装酒馆助手 → 按 `references/frontend-conventions.md` 开头那段告知并二选一，不要硬做。

## 追问

**充分性评估**三项全满足则直接生成：① 形态（A 还是 B）② 形态 A 要"入场者是谁 + 从哪儿开始 + 此刻处境"，形态 B 要"要采集哪些字段 + 步数上限" ③ 界面语气（冷硬公告 / 手写便条 / 档案卷宗）。

不满足则追问，**最多 2 轮、每轮 ≤3 问**，每题 2–3 选项 + 其他。可问的只有这五类：

| 可问 | 例 |
|---|---|
| 形态 | 「A 登场面板：开屏三行字就进正文 / B 建卡向导：先捏人再开局」 |
| 入口走向（A） | 「推门进塔 / 先绕去码头 / 留在原地听」 |
| 采集范围（B） | 「只填基础身份（3 步）/ 身份+性格+装备（6 步）/ 全套（8–9 步）」 |
| 触发位置（B） | 「开场白就是向导 / 正文里出现标签才弹」 |
| 语气与配色 | 「盐白+灯黄 / 夜蓝+铜绿 / 档案黑白」 |

不问：字体、圆角、间距、动画时长——自主决定。

2 轮后仍缺 → 缺失字段补全并标 `【AI补全·可替换】`，不再问。

## 判断标准

- **开屏三十秒内能动手**：A 的第一屏必须能看见「往哪儿走」；B 的第一屏必须能看见「这是什么世界、接下来填几步」。
- **不多话**：界面里不出现"欢迎使用""点击开始"这类说明书句；B 的步骤标签用两到四个字（"基础身份""装备与外观"），不写句子。
- **A 的入口可点可发**：按钮点击后真的发消息，不是装饰；发送前弹确认框（点错就发出去收不回来）。
- **B 的出口是一段可直贴的文本**：Markdown 或纯文本，字段名与角色卡一致；复制按钮一次点成，失败要有手动选中提示。
- **B 能续填**：关掉再回来还在（`localStorage`），进度条上的步骤可点回退。
- 数值、势力、地名与产物**逐字一致**；产物里没有的专名不新造。
- 基调红线（`项目档案.yaml` 的 `基调红线`）在视觉与文案上都不许违反：写"冷硬"就别配粉色渐变。

## 生成

### 形态 A · 登场面板（`templates/opening-ui.html` 起手）

**数据块**（AI 在开场消息里输出一次，九个字段）：

```
<开局界面>
<标题>白潮</标题>
<副标题>盐湖守夜人</副标题>
<一言>潮水每年涨一寸，灯一年比一年暗。</一言>
<角色>祁昭 · 第七塔次席守夜人</角色>
<场景>盐镇 · 第七塔塔顶</场景>
<时间>潮历四十七年 · 第三次涨潮前夜</时间>
<入口1>推门进塔|我攥紧灯油，推开了第七塔的木门。</入口1>
<入口2>先绕去码头|我沿着盐渍的石阶往下走，潮声越来越近。</入口2>
<入口3>留在原地听|我停在门口，听塔里那盏灯芯烧得噼啪响。</入口3>
</开局界面>
```

- `入口N` 格式 `显示文本|实际发送`，`|` 全角半角都认，发送内容里不许再出现 `|`。入口 1–3 条，没有的整行删掉（不留空标签）。
- 字段值一行一个，不许换行、不许含 `<` `>`。
- 数据路径：**B（`$1` 注入）** 或 **C（`getChatMessages`）**。用 B 时 `findRegex` 带捕获组、HTML 里藏 `$1` 的 textarea；用 C 时无捕获组、HTML 自己取本楼。B 更稳，默认走 B。

**界面**（七段，从上到下）：

1. 标题区：`标题` 大字 + `副标题` 小字，基调由 `类型与基调` 定（史诗用衬线大字，日常用无衬线小字）。
2. 一言：斜体或引文样式，一至两行，克制留白。
3. 信息条：`角色` / `场景` / `时间` 三项，定义列表或细线分隔的横排，标签小字、值正常字重。
4. 入口区：`入口N` 渲染成按钮，垂直排列；按钮上是 `显示文本`，下方小字是发送内容前 12 字。
5. 点击：确认框 → `triggerSlash('/send ' + 发送内容)`，按 `references/frontend-conventions.md` 第二节的三级降级写，别只写一行 `triggerSlash`。点击后按钮置 `disabled` 防重复发送。
6. 数据缺失：某字段空就整块不渲染；九字段全空则 `root.innerHTML=''` 留白。
7. 末尾一行极小字的环境注只在用户明确要键盘提示时加。

### 形态 B · 建卡向导（`templates/wizard-ui.html` 起手）

**步骤结构**（固定三段式）：

1. **序章（1 步）**：3–6 张世界观卡片，每张一个短标题 + 两三句话，从 `world-bible.yaml` 直接取（世界是什么、规则/代价、势力、此刻的处境）。不写"欢迎"，不写规则说明书。
2. **字段分组（3–6 步）**：每步 2–5 个字段，字段名与顺序照 `references/stage-2-rolecard.md` 的规范分组（基础身份 / 生存背景 / 势力归属 / 性格与信念 / 装备与外观 / 补充）。枚举型字段用 `select` 且允许"自定义…"（末项用 `__custom__` 占位 + 配套输入框，`templates/wizard-ui.html` 已经写好）；长文本用 `textarea`；其余 `text`。
3. **总览（1 步）**：分组列出已填项 → 生成「角色档案」Markdown → 「复制」按钮（`navigator.clipboard` + `document.execCommand` 兜底）。必填项缺失时在顶部提示缺哪几项，**不硬拦**——用户可能就想先空着，标出来让下游当未定处理。

**必做的四件事**（少了就不是向导，是张表单）：

- **进度条可点**：步骤标签点了能跳到那一步，已完成的加完成态。
- **`localStorage` 续填**：每步切换都存，重开界面自动回到上次那步；键名带项目名（`rpwz:<项目名>:data`），避免两个项目互相覆盖。
- **导出可粘**：Markdown 用 `## 分组` + `- **字段：** 值`，与角色卡字段同名，粘回聊天后阶段 2 能直接照着读。
- **导出前提示必填缺口**，并在说明里写清"这段粘进聊天，让 AI 按它建卡"。

**触发方式**（二选一，问用户）：

- **开场白即向导**：把触发词写进角色卡开场白（`first_mes` 只有这一个词，正则把它换成整份 HTML）。稳，用户一进聊天就看见——开场白是唯一必然出现的一楼。
- **正文触发**：世界书常驻条目要求 AI 在开头输出 `<建卡向导>`。灵活，但依赖模型听话。

触发词写法：优先用成对标签 `<建卡向导>`；用裸词（如 `Create_character`）也行，但要提醒用户这个词在正文里出现时会误触，且 `findRegex` 会把它从正文里抹掉。

**开场白这一步要用户手工做**：本 skill 的 `rolecard.yaml` 是人物设定，不含 `first_mes`。选"开场白即向导"时，交付里必须多一句操作说明——在 SillyTavern 角色卡编辑页，把「第一条消息」改成 `<建卡向导>`（一个字都不多写），点更新。只有这句话在聊天里出现，向导才会被替换出来。

**数据路径**：形态 B 默认 **A（静态替换）**——向导不需要外部数据，字段都写死在 HTML 里。只有当向导要用 `$1` 预填（比如从上一轮读取"玩家已选的势力"）时才走 B。

### 正则

`templates/regex-frontend.json` 改三处：`scriptName`、`findRegex`（A 形态裸词或标签；B 形态带捕获组）、`replaceString`（整份 HTML）。`placement: [2]`、`markdownOnly: true`、`runOnEdit: true`。

### 提示词条目（`frontend-prompt.yaml`）

- 形态 A：内容段写九字段 + 入口格式 + "只输出一次"；`插入位置` 建议"角色卡开场白"或"世界书 · 仅开场时激活"。
- 形态 B：条目极小——`触发时机: 仅开场一次`、`插入位置: 角色卡开场白`、`内容: <建卡向导>`。真正让它工作的是那份 HTML。

## 写回契约

- `stages.5` → `done`（界面做完）/ `partial`（只出数据块与提示词、HTML 待改）/ `skipped`。
- `artifacts` 追加三条：`opening-ui`（HTML）、`opening-ui`（正则 JSON）、`opening-ui`（提示词 YAML），`path` 相对项目根——三条同 type 不同文件是允许的，靠 `path` 区分。
- `naming.ui_tags.opening` → `"开局界面"`（形态 A）或 `"建卡向导"`（形态 B）；写定后阶段 6 不许撞名。
- `hard_settings` 加一条触发约定（`source: 用户确认`）：如"角色卡开场白固定为 `<建卡向导>`"。不进角色卡或世界书，界面就是死代码。
- `decisions` 记：形态、步数与采集范围、触发位置、语气与配色、`【AI补全·可替换】` 清单。

## 退出

- 前端门九条（`references/frontend-conventions.md` 第六节）逐条过，并跑 `python scripts/validate-frontend.py 最终产物/开局前端/*.html`。形态 A 额外验：脏值 `<b>x</b>` 显示成字面文本；删掉整个数据块后界面留白；按钮点两次只发一次。
- 形态 B 额外验：**清空 `localStorage` 重开**能从头填；中途跳步不丢数据；只填一半也能导出且顶部提示缺哪些必填；导出文本里的字段名与角色卡字段名逐字一致；复制在无 `navigator.clipboard` 的兜底路径下仍成功（把 `navigator.clipboard` 置 `undefined` 试一次）。
- 交付时说清四句话：正则怎么导入、渲染开关在哪、提示词条目（或开场白触发词）贴哪里、向导粘回来的那段交给谁（阶段 2）。
- 用户只要粘贴版（不要文件）→ 三个代码块给全，`project.mode = text` 不变。
