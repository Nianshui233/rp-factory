# 阶段 5 · 开局前端

产物 type：`opening-ui`。机制、HTML 骨架、正则格式、提示词条目全在 `references/frontend-conventions.md`——**进入本阶段先读它**，这里只补开局特有的东西。

## 进入条件

- 需要 `naming.world`；有 `project-profile.yaml` 的 `类型与基调` 更好（标题、基调词直接从那里取，不另起炉灶）。
- 有 `rolecard.yaml` / `scene-sheet.yaml` 时从中取登场角色与首个场景；没有就只做世界层，字段留空不许编人名。
- 用户明说要"开局界面 / 开场面板 / 首页 / 目录页"才进。用户只说"美化一下"→ 先问是开局还是每轮状态栏，别猜。
- `project.web_research: true`：界面里要出现真实地名、年代器物、专业术语时先查（`references/web-research.md`），纯虚构世界不查。
- 没装酒馆助手 → 走 `references/frontend-conventions.md` 开头的告知与二选一，不要硬做。

## 追问

**充分性评估**三项全满足则直接生成：① 入场者是谁（角色名或"无名旅人"）② 从哪儿开始（场景）③ 开场这一刻的处境一句话。

不满足则追问，**最多 2 轮、每轮 ≤3 问**，每题 2–3 选项 + 其他。可问的只有这四类，别的不必问：

| 可问 | 例 |
|---|---|
| 入口几条、各是什么走向 | 「三条入口：进塔 / 去码头 / 留在屋里」 |
| 界面语气 | 「冷硬公告 / 手写便条 / 档案卷宗」 |
| 要不要「继续上次」入口 | 长线项目才问 |
| 配色倾向 | 「盐白+灯黄 / 夜蓝+铜绿」，给两三个具体方案 |

不问：字体、圆角、间距、动画——这些是本阶段自主决定项。

2 轮后仍缺 → 缺失字段补全并标 `【AI补全·可替换】`，不再问。

## 判断标准

- **一眼看出这是什么故事**：标题 + 一句基调词 + 一处场景，三者同屏可见，不用滚动才看到重点。
- **入口可点可发**：每个入口按钮点击后向聊天发送该入口的正文，不是装饰。
- **不多话**：界面里不出现"欢迎使用""点击开始"这类说明书式句子；信息密度高、字数少。
- 数值、势力、地名与产物**逐字一致**；产物里没有的专名不新造。
- 基调红线（`project-profile.yaml` 的 `基调红线`）在文案上不许违反：写"冷硬"就别配粉色渐变。

## 生成

### 一、数据块（AI 输出什么）

开局消息末尾输出一个 `<开局界面>` 块，字段固定这九个：

```
<开局界面>
<标题>白潮</标题>
<副标题>盐湖守夜人</副标题>
<一言>潮水每年涨一寸，灯一年比一年暗。</一言>
<角色>祁昭 · 第七塔次席守夜人</角色>
<场景>盐镇 · 第七塔塔顶</场景>
<时间>潮历四十七年 · 第三次涨潮前夜</时间>
<入口1>推门进塔|我攥紧灯油，推开了第七塔的木门。</入口1>
<入口2>先绕去码头|我沿着盐渍的石阶往下走，潮声越来越近。</入口2>
<入口3>留在原地听|我停在门口，听塔里那盏灯芯烧得噼啪响。</入口3>
</开局界面>
```

- `入口N` 格式 `显示文本|实际发送`，`|` 全角半角都认，发送内容里不许再出现 `|`。
- 入口 1–3 条；只有一条时也只写 `入口1`，其余整行删掉（不留空标签）。
- 字段值一行一个，不许换行、不许含 `<` `>`。
- 标签一律 `<开局界面>`，与正则、HTML 的 `TAG` 三处一致。

### 二、HTML（`templates/opening-ui.html` 起手）

七段结构，从上到下：

1. 标题区：`标题` 大字 + `副标题` 小字，基调由 `类型与基调` 定（史诗用衬线大字，日常用无衬线小字）。
2. 一言：斜体或引文样式，一至两行，克制留白。
3. 信息条：`角色` / `场景` / `时间` 三项，用定义列表或细线分隔的横排，标签小字、值正常字重。
4. 入口区：`入口N` 渲染成按钮，垂直排列；按钮上是 `显示文本`，`title` 或按钮下方小字是发送内容的前 12 字（让用户知道点了会说什么）。
5. 点击：`await triggerSlash('/send ' + 发送内容)`；点击后按钮置 `disabled` 并加 `.is-sent`，防连点重复发。
6. 数据缺失：某字段为空就整块不渲染（缺 `角色` 就不出信息条那一项），九字段全空则 `root.innerHTML=''` 留白。
7. 末尾可加一行极小字的环境注（如"按 C 继续"）——只在用户明确要键盘提示时加。

### 三、正则（`regex-opening.json`）

照 `references/frontend-conventions.md` 第四节：`findRegex: "/<开局界面>[\\s\\S]*?<\\/开局界面>/g"`，`scriptName: "RP · 开局界面"`，`placement: [2]`，`markdownOnly: true`，`runOnEdit: true`。

开局块通常只出现一次（开场白）。若用户把界面放进角色卡开场白，提醒一句：开场白里的标签同样被正则处理，但**该楼层必须有消息元素**，开场白默认就是 0 楼，正常。

### 四、提示词条目（`frontend-prompt.yaml`）

内容段写清九字段、入口格式、只输出一次；`插入位置` 建议"角色卡开场白"或"世界书 · 仅开场时激活"。

## 写回契约

- `stages.5` → `done`（做完界面）/ `partial`（只出数据块与提示词、HTML 待用户改）/ `skipped`。
- `artifacts` 追加三条：`opening-ui`（HTML）、`opening-ui-regex`（JSON）、`opening-ui-prompt`（YAML），`path` 相对项目根。
- `naming.ui_tags.opening` → `"开局界面"`（新建键区项，之后阶段 6 不许改名）。
- 界面里用到的专名（角色、场景、地名）必须已在 `naming` 里；新出现的名字先问用户，命名门会查。
- `decisions` 记：入口走向怎么定的、语气与配色选了什么、`【AI补全·可替换】` 项清单。

## 退出

- 前端门七条（`references/frontend-conventions.md` 第六节）逐条过：标签三处一致、字段两处一致且能追到产物、`markdownOnly: true`、`replaceString` 含 ```html、HTML 含 `<body>`、无外链与 `eval`、无标签时留白。
- 亲手造一次误数据：把一个字段值写成 `<b>x</b>`，确认界面显示成字面文本；再删掉整个 `<开局界面>` 块，确认界面安静留白。
- 交付时说清三句话：正则 JSON 怎么导入、酒馆助手渲染开关在哪、提示词条目贴哪里（`references/frontend-conventions.md` 第四节末与第五节）。
- 用户只要粘贴版（不要文件）→ 三个代码块给全，`project.mode = text` 不变，产物名照旧写进交付说明。
