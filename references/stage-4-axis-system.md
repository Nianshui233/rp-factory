# 阶段 4 · 数值系统

产物 type：`axis-system`。骨架：`templates/axis-system.yaml`。格式与降级链回 `references/interview-protocol.md`。

## 进入条件

- 可从阶段 1 直接进入，**不需要角色卡在前**。有 `naming.world` 时读其规则上限（数值不能超出世界能给出的量级，如"魔法极稀有"就不该有全民众堕落的机制）。
- `naming.axes` 里有 `provisional: true` 的项（阶段 2 / 3 先行写下的轴名）：逐条确认或改名。改名必须回写已引用它的产物并记入 `decisions`——只改契约不改产物，就是本包要消灭的那种漂移。
- 接管 `naming.axes` 后删掉 `provisional` 键，本阶段成为该键区的独占写者。
- 用户直接给"做一个好感度系统"也能进，不必先有世界观。
- `project.web_research: true`：先按 `references/web-research.md` 检索有无通行的数值口径（原作官方分级、圈内好感度习惯、真实题材对应量级），记进 `制作文件/项目记录/检索来源.md`，查完才动笔。

## 追问

**充分性评估**三项**全部满足**则直接生成：

1. **维度**：用户给了至少 1 个可量化维度名称
2. **数值**：可推断数值范围与变化方向
3. **对象**：可确定系统作用于谁。若对象**多于一人**（群像 / 后宫 / 多人关系），必须在这一步定下实现方式，见下「多目标」

不满足则追问：**最多 2 轮，每轮 ≤4 问**，每题 2–3 选项 + 其他。用户委托决策 → 自主补全并标 `【AI补全·可替换】`。**2 轮后仍有缺失 → 全部补全，不再追问**，这是本阶段与阶段 1 的差别：数值系统不给无限轮。

## 判断标准

### 四条核心原则

- **闭环**：触发 → 数值变化 → 行为表现，链路无断点。断在哪一环就补哪一环，别加抽象描述。
- **可计算**：所有数值变化由纯数值字段 + 公式得出，禁止文本型运算符（写 `0.5`，不写 `"×0.5"`）。
- **可观察**：相邻阈值之间至少 2 项 `behavioral_signs` 存在可感知差异。两条都是"态度变好"等于没写。
- **显式标注**：用户未提供的信息标 `【AI补全·可替换】`；缺失且无法推断标 `【未知】`。

### 多目标：一条轴不够时

`affection` 这类"某人对玩家的态度"在群像里**不能只有一条全局值**——否则全局到 60 时十四个人一起变，玩家对谁都没法经营。对象多于一人时三选一，写进产物与 `decisions`：

| 方案 | 写法 | 适用 |
|---|---|---|
| **A 逐人一份**（推荐） | `axes[].targets: [char_a, char_b, …]`，每个 target 一行 `initial` 与当前值；`thresholds` 共用一套 | 人数 ≤ 15、关系是主线 |
| **B 分组** | `targets` 按势力/亲疏分 2–4 组（`inner_circle` / `neighbors` / `outside`），每组一行 | 人数 > 15 或关系不是主线 |
| **C 降级为气氛值** | 轴改名（`building_mood` / `tension`），并在 `decisions` 写「不做逐人数值，冲突靠剧情判定」 | 沙盒日常剧、用户不要数值 |

选 A / B 时，产物里必须有一句给 AI 的读法：「每次互动只改被互动那个 target 的值，其它 target 不动；没有互动的 target 按 `decay` 规则回落」。阶段 7 打包时这条轴要进包，否则数值在角色扮演里等于不存在。

### 硬规则

- `thresholds` 与 `boundaries` **按轴名分键**（`thresholds.<轴名>` / `boundaries.<轴名>`）：一个轴一套阈值与上下界，多轴就多套。
- 每个轴的 `thresholds.<轴>.levels` **至少 3 级**，完全覆盖该轴的 `range`，**无间隙无重叠**。
- `direction: ascending` 的轴，其所有阈值行的 `calc_mod.negative` 必须为 `0`；`descending` 的轴，`calc_mod.positive` 必须为 `0`。
- **至少设计 1 种反直觉事件**（看似正面实则负面，或反之）。
- 数值字段为纯数字；修正系数 `1.0` = 无修正。
- 变量名全小写英文下划线分隔；描述文本中文。
- `initial` 必须落在 `range` 内。
- 公式用伪代码与标准运算符（`*` `+` `-` `/` `round()`）。

### 字段语义（写错就整卡不可执行）

- `base`：事件基础值，参照 `base_range`；事件与 base 由 AI 运行时判定，须落在 `base_range` 内。
- `threshold_mod`：`base > 0` 取**该轴当前阈值**的 `calc_mod.positive`；`base < 0` 取 `calc_mod.negative`。
- `context_mod`：情境修正系数，取**第一个匹配项**的 `factor`，无匹配为 `1.0`。
- `diminish_mod`：同类事件同会话第 N 次触发的衰减系数。"同类"按触发**意图**归类，非字面匹配；第 4 次及之后均取末位值；新会话重置。
- **多事件合并**：单次交互含多个触发时，正负事件分别处理 → 取各自最高 `|base|` 的事件全额、其余 ×0.25 累加 → 正负 delta 合并为单一 delta。
- **裁剪顺序**：`caps`（per_interaction → per_session）→ 该轴的 `boundaries`，顺序不可颠倒。

## 生成

按 `templates/axis-system.yaml` 填六核心块，复杂系统再按需启用四扩展块（`context_modifiers` / `decay` / `anti_exploit` / `interactions`），不用的整段删掉。

`meta.display.mode` 决定数值是否出现在正文：`explicit`（正文输出数值，需填 `format` 与 `position`）/ `implicit`（仅行为体现，只填 `mode`）。默认 `implicit`——多数 RP 里把数值写进正文会破坏代入感。

`runtime` 是标准模板，无特殊需求原样复用，不要重写。`calculation` 与 `caps` 是全卡共用的（不按轴分键）——如果两条轴的量级差很远，宁可拆成两张卡，不要把两套量级塞进一个 `base_range`。

**交付四件套**：

1. **YAML 卡**（一个 yaml 代码块）
2. **设计说明** ≤5 句：轴为什么这么切、阈值为什么这么分、反直觉事件想制造什么
3. **补全清单**：所有 `【AI补全·可替换】` 项逐条列出
4. **运行示例**：至少 1 正面 + 1 负面触发，展示完整计算过程——从 `base` 取值、`threshold_mod`、`context_mod`、`diminish_mod` 一路乘到 `caps` 裁剪与最终数值，再对应到行为表现

**落地路线**（交付末尾一段）：本卡抽离了运行环境，可落到三条路线——纯提示词（把卡直接放进世界书，AI 凭规则心算）、变量框架（每个 `axis` 落成 schema 字段，`calculation` / `caps` / `decay` 写成更新检查）、阶段控制器（把 `thresholds.levels` 每段对应一条世界书条目，按轴值加载）。

本包现在三条都能落：

- 纯提示词：本阶段结束就够用，把卡放进世界书让 AI 心算。
- 变量框架：交给阶段 `mvu`——把每条轴投影成 zod 字段（`range` → `clamp`、`initial` → `catch`/`prefault`），配 `[initvar]` 与更新条目，数值就跨楼记住了。
- 阶段控制器：交给阶段 `ejs`——把 `thresholds` 的每一档写成一条禁用条目，控制器按轴值 `getwi` 加载。**只在"整段内容随档位整体切换"时才做**，只是报档名不值得。

落地选哪条由用户定：`axes` 只交轴表，`mvu` / `ejs` 各自独立可选。别在 `axes` 里替用户决定，也别承诺"变量会自动更新"——那是 `mvu` 阶段的产物。

## 写回契约

- 独占接管 `naming.axes[]`：每项 `{name, range, initial, levels}`，删掉 `provisional`。
- `stages.4` → `partial` / `done`。
- 改名：改 `naming.axes` 后回写引用它的产物（角色卡里提到该轴的、场景卡里提到该轴的），记入 `decisions`。
- `hard_settings[]`：用户确认的数值上限（"好感度最高只到99，100不可能"这类）追加，`source: 用户确认`。
- `pending[]`：仍留的 `[待定：…]` 登记。
- 本阶段产物不进契约正文——`thresholds` / `calculation` / `boundaries` 都留在 `axis-system.yaml` 里，契约只记名字。

## 退出

- 自检门：逻辑一致性看"轴方向与 `calc_mod` 是否矛盾"；覆盖度看"阈值级数与 `behavioral_signs` 数量"；内容边界层看"轴本身是否越界"；格式看"数值是否纯数字、变量名是否小写下划线"。
- 命名门四步通过：轴名与契约一致，且与角色卡 / 场景卡里的提法一致（"好感度"不能在一处叫"好感"、另一处叫"亲近值"）。
- 交付四件套齐备后交付 → 回写契约 → **阶段收尾一检** `python scripts/check-stage.py axes <项目根>`（内部查契约），退出码 0 → 阶段结束。
- 用户只要轴名不要数值：可以，写进 `naming.axes` 交出去，`stages.axes` 置 `partial`，并说清没有数值的实现会让 AI 自行发挥。
