## 二、Review Focus 五项验证

**1. 只说「我只要一张盐湖的守夜人哨塔场景卡」**

走的是补采访问而不是整张 `[待定]`：先问三题（世界有没有超常力量 / 社会秩序大致形态 / 技术上限），三题都答了，于是场景卡直接有内容可写。若三题都答不上，卡片只有 `概览` 与 `边界` 两块能填，其余 `[待定：…]` 并登记进 `contract.pending`——这是设计意图。**通过。**

**2. 把「守夜人」改名成「夜巡者」**

命名门四步读两处（契约 + 产物），扫出：`world-bible.yaml` 的 `势力列表`、`AI即兴角色约束`、`规则`；`rolecard.yaml` 的 `identity.appearance` 与 `background`；`scene-sheet.yaml` 的 `生态.常驻者与管理者`；以及 `contract.yaml` 的 `naming.factions`。四处要改，问用户一句"全改还是只改称谓"，选定后统一回写并记入 `decisions`。**通过**（这一项暴露出四步里的第 2 步必须写"扫产物"，只扫契约会漏）。

**3. 说「你来定」**

产物里出现 `【AI补全·可替换】` 的项只有三处（`元信息` / `类型与基调` 已移出终稿，不计入）：`world-bible.yaml` 的 `关键历史与时间线.被遗忘或篡改的历史`、`rolecard.yaml` 的 `background.turning_point`、`scene-sheet.yaml` 的 `关键区域.地窖` 的档案柜数量。三处都在 README 之外单独列了清单交用户确认。**通过。**

**4. 要求「给我能粘贴的」**

终稿渲染移除全部 `#` 注释与被注释掉的可选结构，代码块外只剩设计说明、补全清单、待确认清单、运行示例。**起初不通过**——见第三节第 1 条。

**5. 四份产物对同一实体用同一个名字**

抽查六个名字：`白潮` / `守夜所` / `第七塔` / `祁昭` / `灯芯值`（`wick`）/ `潮压`（`tide`）。四份产物与契约一致。`湖心教团` 在角色卡里没出现，不算冲突。**通过。**

## 三、跑不下去 / 暴露的问题（已修）

**1. 交付形态自相矛盾（已修）**

`dual-mode.md` 原文写"文本模态代码块外只允许补全清单与待确认清单"，但阶段 2 要求交付"设计说明 ≤5 句"、阶段 4 要求交付"运行示例（≥1 正 + 1 负，含完整计算）"。三处规则互斥，写 dry-run 时无法判断该不该输出设计说明。
改法：`dual-mode.md` 与 `pipeline.md` 的输出纪律、`SKILL.md` 第九节统一为"代码块外允许四样：设计说明 / 补全清单 / 待确认清单 / 运行示例"。

**2. 多轴数值卡没有位置放阈值（已修）**

`templates/axis-system.yaml` 的 `thresholds` 与 `boundaries` 是单套扁平结构，`axes` 却是列表。双轴（`wick` + `tide`）时两套阈值无处安放，`interactions.cross_axis` 也失去依据。
改法：`thresholds` 与 `boundaries` 改为按轴名分键（`thresholds.<轴名>.levels`），`calculation` 与 `caps` 仍全卡共用；阶段 4 的硬规则同步改为"每个轴的阈值 ≥3 级、方向约束按轴判"，并补一句"两轴量级差太远就拆成两张卡"。

**3. 委托决策的硬设定进不了收敛门（已修）**

`pipeline.md` 的收敛门要求"硬设定已有 ≥3 条用户确认"，但用户说"你来定"时，补全项只能标 `【AI补全·可替换】`，永远凑不满 3 条"用户确认"，收敛门无法通过。
改法：计法改为"用户确认的，或用户明确委托决策后标 `【AI补全·可替换】` 且已告知的"——委托不等于未定，但必须在末尾说明。

**4. 开工时没有问工作区这一步（已补）**

原本 `SKILL.md` 一上来就是"开工前读 pipeline"，没说产物往哪里落；`templates/contract.yaml` 只写"复制到项目根"；工程模态又把目标定成 `contract.project.name` 命名的目录。同一件事三处说法不一致，也没人先问用户一句。
改法：`SKILL.md` 新开第二节「工作区（第一步）」+ 硬门第 0 条「工作区门」；`dual-mode.md` 工程模态路径改为 `<工作区>/<世界名>/创作痕迹/产物/`；`contract-schema.md` 补 `project.workspace` 与 `artifacts[].path` 相对项目根的写法；`interview-protocol.md` 新增第五节「痕迹记录」定义 `创作痕迹/创作记录.md` 的四节格式。

## 四、没修但记下

- **`caps` 与 `boundaries` 的量级关系没有校验规则**：`per_session.min` 设成 `-40`、轴 `range` 是 `[0,100]`，一晚上能掉四成，合不合理靠设计者判断，规则层不拦。这一条属于"品味问题"，加规则会误伤别的系统，暂不处理。
- **`places[].scope` 是自由文本**：`loc_seventower` 的 `scope` 写的是"堤线最末哨塔，已熄灯十二年"，这与 `hard_settings.H03` 重复。契约允许这种重复，但改名时要改两处。记下，不改结构。
- **场景卡的 `线索` 强制 ≥3 条**：这次写了 4 条，其中第 4 条（老邵的口述）其实是 NPC 信息而非场景信息，位置勉强。规则层不区分，靠判断。

## 五、阶段 6（表现层）跑出来的东西

**链路**：AI 每轮末尾输出 `<状态栏>` → ST 正则（`markdownOnly: true`）整块换成 ```html 代码块 → 酒馆助手认代码块里有 `<body>`，渲染成 iframe → iframe 里 `getChatMessages(getCurrentMessageId())` 读本楼原文，拆字段，画条。

**产物对应**：`statusbar-ui.html` 的 `FIELDS`（灯芯 0–100 `dir:down` warn 34 / danger 15；潮压 0–100 `dir:up` warn 60 / danger 82）逐项抄自 `axis-system.yaml` 的 `range` 与 `direction`；`regex-statusbar.json` 的 `replaceString` 内嵌同一份 HTML；`frontend-prompt.yaml` 的 `一致性` 段登记 `标签: 状态栏` 与四字段。

**跑过的验证**（本地 node + DOM 桩，不是真酒馆）：

| 情形 | 期望 | 实际 |
|---|---|---|
| 本楼 72 / 上一楼 80 | 条 72%、`↓8` | 一致 |
| 潮压 42 / 上一楼 30 | 条 42%、`↑12`，不上色（up 轴，42 < 60） | 一致 |
| 越界 140 | 条钳满 100%，数字照写 140 | 一致；`灯芯 140` 按 down 轴判不危险，`潮压 140` 判危险 |
| 脏值 `<b>x</b>` | 显示字面文本 | 一致（`esc()` 在拼 `innerHTML` 前生效） |
| `未知` | 整条隐去 | 一致 |
| 本楼无 `<状态栏>` | 留白，不报错 | 一致（`root.innerHTML=''`） |
| 正则与 HTML 一致性 | `TAG` / `findRegex` / `一致性.标签` 三处相同；`FIELDS` 与 `一致性.字段` 两组相同 | 一致（脚本逐项比对） |

**暴露的问题（已写进规则）**

1. **我按名字猜单位，猜错了。** 先写成 `潮压 0–1 小数`，`axis-system.yaml` 里其实是 `range: [0, 100]`、`initial: 22`。若不逐项抄 `range`，同一根轴在界面里的比例会是错的。→ 阶段 6 的「判断标准」与「退出」都写明：`FIELDS` 的 `min/max` 必须逐项对 `range`，不一致就改界面、不改产物。
2. **越界值该不该擦干净？** 决定照原样显示数字、只把条钳住：数字漂移是模型的问题，界面替它抹平就看不见了。→ 写进阶段 6「退出」。
3. **无插件版从一开始就不成立。** ST 在 `messageFormatting` 后要过 `DOMPurify.sanitize()`，`ADD_TAGS` 只有 `custom-style`，`<script>` 一律被删。所以"$1 注入 + 内联脚本解析"那条路是死的。→ 表现在 `references/frontend-conventions.md` 开头的三条硬规矩里，第一条就是"正则必须仅格式显示"。

## 六、阶段 5（开局前端）跑出来的东西

**形态**：用户在"登场面板 / 建卡向导"里选了后者——先捏人，再进故事。向导 8 步：序章（6 张世界观卡）→ 基础身份 → 势力归属 → 心理 → 关系与语言 → 装备与外观 → 底线与去向 → 角色总览。

**字段来源**：字段名与分组照 `references/stage-2-rolecard.md` 的规范 1–6 取名（`姓名` / `出身` / `faction` / `goal` / `close` / `speech` / `gear` / `taboo` …），不是自己另造一套；必填四项 `姓名` / `随身灯油（天）` / `归属` / `目标`，其中灯油是白潮特有的"续命资源"，由此进入角色卡而不仅是数值卡。

**触发**：角色卡「第一条消息」写 `<建卡向导>`；`regex-opening.json` 的 `findRegex` 是裸标签、无捕获组，`replaceString` 内嵌整份 HTML（路径 A 静态替换，15 KB）。向导只靠 `localStorage`（`rpwz:盐湖守夜人:data`）续填，不用任何聊天 API，复制走 `navigator.clipboard` → `execCommand` 兜底。

**跑过的验证**（同上是 DOM 桩，不是真酒馆）：

| 情形 | 期望 | 实际 |
|---|---|---|
| 空数据进总览 | 提示"还差必填项：姓名、随身灯油、归属、目标"，并提示还没填内容 | 一致 |
| 只填姓名与灯油 | 导出 `# 祁昭 — 角色档案` + 分组 `- **姓名：** 祁昭`；未填的字段不出现 | 一致 |
| 目标值含 `<p>` | 总览里显示字面 `&lt;p&gt;`，不解析成标签 | 一致（`esc()` 在拼 `innerHTML` 前生效） |
| 跳步 | 进度条可点回退，切步时 `collect()` 落盘，回头值还在 | 一致（`data` 全局 + 每次 `collect` 存 `localStorage`） |
| 清空 `localStorage` 重开 | 从序章开始，无残留 | 一致（`load()` 失败回落 `{}` / `0`） |
| `findRegex` 与 HTML 一致性 | 路径 A：无捕获组、HTML 里无捕获组占位符 | 一致（`grep -c '$1'` = 0） |

**暴露的问题（已写进规则）**

1. **向导和"接回正文"之间缺一步。** 向导导出的是一段 Markdown 档案，用户得自己粘回聊天让 AI 建卡；若只是给了 HTML 而没说这句，向导就是个孤岛。→ 阶段 5 的 `OUTRO` 与交付说明都写明"把这段粘进聊天，让 AI 按它建卡"。
2. **向导的必填项不该硬拦。** 用户可能故意先空着（等剧情里再定）。→ 总览顶部只提示缺哪几项，按钮仍可点，缺的值按 `[待定]` 语义交给下游。
3. **"开场白即向导"要用户手工改一处。** 本 skill 的 `rolecard.yaml` 是人物设定，不含 `first_mes`；不去 ST 角色卡编辑页把「第一条消息」改成 `<建卡向导>`，正则永远不触发。→ 写进阶段 5 的"触发方式"与契约 `hard_settings`（`H07`）。

## 六、阶段 7（交付）跑出来的东西

**收尾只问一句**：原生 / 酒馆三件套 / 两者都要。这次选「酒馆三件套」，于是 `最终产物/` 里只有三个文件，其余全在 `创作痕迹/产物/`——**交付前 `最终产物/` 一直是空的**，那是交付目录不是工作目录。

**三件各管一件事**：

| 文件 | 内容 | 为什么分开 |
|---|---|---|
| `白潮（纯净）.json` | 卡 v2：`description` 5,943 字（世界骨架 + 住户/场景/数值速查 + 一句"以上是设定"）、`first_mes = <建卡向导>`、`system_prompt` = 项目档案「本文档对AI的核心指令」、**无 `character_book`、`extensions.regex_scripts = []`** | 设定每轮都在场，但不再是"把整张卡塞进描述"：人物与细节交给世界书按需加载 |
| `正则.json` | 数组 2 条：`/·建卡向导/`（无捕获组，静态替换 15 KB）与 `/<状态栏>([\s\S]*?)<\/状态栏>/g`（捕获组 + `$1` 注入） | 界面迭代不用重导卡；酒馆的正则导入认数组，一次导完 |
| `白潮 世界书.json` | native 形状 `{"entries": {"0": …}}`，15 条：8 常驻（世界观 + 数值与判定 + 状态栏协议）、7 关键词（祁昭 + 6 地点） | 文件名就是酒馆里的书名；卡里 `extensions.world` 与它同名，导完自动挂上 |

**为什么不做单文件内嵌卡**：内嵌的确少一步，但改一条设定就要重导整张卡，世界书与正则也没法单独迭代；用户还得在两个入口之间来回找。三份分开交，用户自己装配，每件都能单独换。

**装配四步**（写进 `creator_notes`）：世界书 → 卡 → 正则 → 打开"消息渲染"。

**校验**：`python scripts/validate-st-package.py "最终产物" --contract "创作痕迹/contract.yaml"` → 19 项 0 失败 0 警告（三件齐全、卡纯净、书是 native 且 `uid` 对齐、`extensions.world` == 文件名、`first_mes` 被正则接住、占位符 0 命中）；`validate-contract.py` → 14 项 0 失败（含 C13「最终产物交付前空、交付后三件齐」）。

**暴露的问题（已修）**

1. **`extensions.world` 与书名必须一致**：世界书名 = 世界书**文件名** = `extensions.world`，默认 `<世界名> 世界书`；卡片名 `st_name` 是另一个值（卡文件名带「（纯净）」）。不一致时 ST 建完书不会自动挂。校验器 X03 盯这一条。
2. **世界书只认 native 形状**：`{"entries": {"0": …}}` 映射、`key` / `order` / `position: 0–7`。卡内 v2 数组形状（`keys` / `insertion_order` / `before_char`）导进世界书面板会把参数全丢掉，校验器 W01 直接判 FAIL。
3. **占位符会漏进运行时**：早期 `description` 里有 15 处 `【AI补全·可替换】`，模型会把它当设定读。现在 X05 对三件一起扫、强制 0 命中，模板里那句 `unknown_handling` 也改成了运行时口径。
4. **常驻预算定得太死**：原 5,000，数值条目一进来就爆。改法：预算提到 8,000（单条 ≤1,000），超了先问自己"真的每轮都要吗"。
5. **单文件卡是错的形**：内嵌世界书 + 内嵌正则看着省事，实际改一条设定就要重导整卡。→ 改成三件套（`docs/specs` §23）。


## 七、阶段 `mvu` / `ejs` 跑出来的东西

先拿真实项目《爱情公寓》手搓验证过一遍（`H:/RP创作/未命名项目`），再回来补 dry-run。真机结论：`<JSONPatch>` 的 `replace` / `delta` 都被执行、逐人独立成立、正文确实跟着数值变了。

1. **`.min/.max` 会拒整条更新**：`z.coerce.number()` 遇 `'很高'` 先产出 `NaN`，在 `.transform` 之前就抛 `ZodError`，整楼更新作废。必须 `.catch(初值)`，夹取放到 `.transform` 里。
2. **`[initvar]` 的 `uid` 必须等于 `entries` 的键**：导出时给 9 条写了 `uid: 1033…1041` 而键是 `"33"…"41"`，酒馆面板按 `uid` 索引，取不到就静默不渲染——磁盘上 42 条、面板里 33 条。
3. **卡内脚本默认不启用**：`extension_settings.settings.script.enabled.characters` 不含这个 avatar 时脚本根本不跑，且不报错。脚本跑在独立 iframe 里，`Mvu` 挂在 `window.parent`。
4. **`character_book` 不会自动变世界书**：导入卡只写角色文件，`.json` 里的书要单独导。
5. **示例初值必须与 `prefault` 不同**：全相等时"initvar 读没读到"根本验不出来。
6. **控制器只在"整段切换"时值得做**：书里已有阈值表时，只报档名的控制器与它是重复的。
